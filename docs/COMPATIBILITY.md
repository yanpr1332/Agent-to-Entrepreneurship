# Windows / macOS 双平台兼容标准

## 硬性决策

Windows 是首要开发和调试平台，但 macOS 不能留到 Windows 完成后再移植。共享业务逻辑、数据结构和用户界面；所有 OS 专有功能必须走抽象接口并单独验证。

## 功能矩阵

| 能力 | Windows | macOS | 验收要求 |
| --- | --- | --- | --- |
| 任务、日历、知识库 | 必须 | 必须 | 相同核心功能、相同数据语义 |
| 离线编辑与本地存储 | 必须 | 必须 | 断网可读写、重新联网不丢数据 |
| 官方 API 同步 | 必须 | 必须 | OAuth/回调、超时、授权撤销稳定 |
| 通知、托盘、开机行为 | 必须 | 必须 | 符合两平台权限和用户偏好 |
| Obsidian/文件导入 | 必须 | 必须 | 文件路径/权限/中文文件名无问题 |
| 语音处理 | 目标 | 目标 | ASR/FFmpeg 必要依赖独立打包或可选安装 |
| 轻度专注 | 必须 | 必须 | 可随时退出，不影响重要系统能力 |
| 应用/网站限制 | 单独实现 | 单独实现 | 权限、安全退出、失败恢复实测 |
| 团队同步及聊天 | 目标 | 目标 | 双平台角色权限与冲突行为一致 |

## 发布与测试

- Windows：优先测试 Windows 11 x64；明确后续 Windows ARM64 支持计划。
- macOS：测试 Apple Silicon 和 Intel（如用户覆盖确有需要），明确定义最低支持系统版本。
- 持续集成：每次合并前构建和自动测试 `windows`、`macos`；原生权限相关功能增加真实设备测试。
- 安装包：Windows `.msi`/安装器；macOS `.app`/`.dmg`，正式分发前签名和公证。
- 多系统一致性：同一用户数据能导出/导入，避免硬编码路径、平台专用编码和 WSL 依赖。

## macOS 专注模式注意事项

Apple 的 App Sandbox 和文件权限会限制第三方应用的访问范围。不可假设可以使用 Windows 的进程控制机制或把 iOS 的 Family Controls 框架直接用于普通 macOS 应用。严格限制能力需要逐项做可行性验证，受限时必须明确降级，绝不承诺“无法绕过”。

- Windows ARM64 是否首发。
- 自律限制功能在各平台的最高可用能力及 OS 权限要求。
- 正式签名、公证与安装包发布渠道。
