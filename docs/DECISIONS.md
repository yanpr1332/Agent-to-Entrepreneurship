## 技术候选及外部条件（尚需 W3/W4 验证）

- Tauri 2 + React/TypeScript + Rust 的桌面架构。
- SQLite 本地优先；账号、跨设备同步和团队协作需要云端服务，FastAPI/PostgreSQL/对象存储只是候选实现。
- Markdown 文件与 Obsidian 兼容；Whisper/FunASR 转写。
- Canvas、SJTU 教务、学校邮箱需真实接入；应用审批和 OAuth 范围须核实。
- Google/Outlook 日历和 Notion 的 OAuth 正式发布条件与数据映射。
- 所有 P0 模块需可用，但模型硬件能力、严格专注限制、云同步容量与加密方案均须先验证。

## W4 开发计划与 V0.1 内部 Alpha 决策（2026-11-07）

| 编号 | 已确认决策 |
|---|---|
| W4-DEC-01 | 团队共五名学生，时间受学业约束，主要由 AI 辅助代码生产；质量与速度平衡。不将五人固定绑定到永久岗位或预先固定所有任务，按责任域和可用时间动态认领。 |
| W4-DEC-02 | 团队使用 Windows/macOS 混合环境；五人通过互联网云端共享工作空间；两种系统都必须用于原型演示和测试。 |
| W4-DEC-03 | 云端方案采用 C：先进行最小技术验证，再决定是否采用 Supabase。Supabase 是优先候选，不是已最终锁定的正式云端架构。 |
| W4-DEC-04 | Canvas 支持用户配置实例地址，认证设计同时支持 Token 和 OAuth；Token 优先用于开发者本人本地验证，OAuth 是多用户正式授权路径。邮件采用通用 IMAP/SMTP，优先保证交大邮箱真实收发。 |
| W4-DEC-05 | 联系老师/学校 Canvas 管理员申请 Developer Key 是最高优先级并行任务；个人 Token 仅限开发者本人本地验证，不得共享给其他成员。 |

### W4 范围说明
- 目标于 2026-11-25 交付 V0.1 内部 Alpha；不是应用商店发布，也不是完整正式产品发布。
- 八大模块全部进入原型并具备基础可操作闭环；PRD 正式 P0/P1/P2 不因 Alpha 时间表而更改。
- Canvas 真实读取与交大邮箱真实收发是 Alpha 明确必交付项；真实授权受阻时标记 Blocked，不以 Mock 冒充。
- 五人真实协作必须使用独立账号和服务端权限隔离。
- AI 可产生任务/日程候选，但用户确认后才能写入；邮件发送每次独立确认。
- 五人责任域是灵活边界，不是固定人岗；每个具体 Task 只设临时 Driver 和 Reviewer，并在 Issue/PR 中记录修改范围和证据。
- W4 文档归档不等于 W5 代码开发授权；W5 启动需另行明确许可。
