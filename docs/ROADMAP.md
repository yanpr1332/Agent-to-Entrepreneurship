# 版本规划与验收（草案）

以下是小规模团队的初步工作量估计，不是承诺工期。学校授权、真实 Mac 测试设备、云端能力和安全审查会明显影响进度。

## 阶段 0：准备与可行性（粗估 2–3 周）

- 完成 PRD、数据模型、交互线框图及模块边界。
- 验证 Tauri 2 在 Windows/macOS 的编译、存储、通知与安装。
- 检查交大 Canvas、开放 API 的授权要求，试读取课表/作业并处理分页限流。
- 确认至少一种邮箱的只读授权与增量同步可行性，并核实发信/草稿权限边界及学校邮箱的适配可能。
- 建立 CI、代码规范、Issue/PR 模板和测试策略。
- 确定各平台安全可实现的专注能力上限。

**阶段门槛**：双平台都能运行最小桌面壳和本地数据库；接口和权限风险有记录。

## 阶段 1：MVP（粗估 8–12 周）

- 今日/本周工作台和统一收件箱。
- 课程、事件、作业、任务、截止与计划执行时间、提醒及基础冲突检查。
- Canvas/SJTU/ICS 的基础只读导入，授权不可用时提供手工路径。
- 一个邮件连接器的只读同步与基础规则/轻量 AI 事项提取：生成待确认的待办和日历建议，保留邮件来源与去重。
- PDF/Markdown 资料导入、分类、基础搜索。
- 简单专注计时和任务耗时记录。
- 基于规则的自动学习时段建议；用户手工调整。
- Windows/macOS 双平台打包、测试、离线使用。

**验收**：实际学生能在两种系统上管理一学期的课程和个人任务；离线工作，数据不丢；学校 API 暂不可用也能手工操作。

## 阶段 2：智能化与协作（额外粗估 10–16 周）

- PDF/录音转写、OCR、Obsidian 集成、源文引用的问答和复习卡片。
- AI 动态重排、知识库关联学习规划。
- AI 邮件拟写、润色、回复/回复全部/转发、草稿保存和用户监督发送；发送权限单独授权、逐次人工确认，并处理重复发送风险。
- 两平台各自实现安全可退出的应用/网站限制；积分与桌宠反馈。
- 团队工作空间、角色、共享任务、文件和基础聊天，个人待办与团队进度联动。
- 多设备同步、团队权限、冲突处理和可审计日志。

**验收**：3–5 人能够完成实际课程小组项目；邮件可在用户审核下正确生成事项与草稿，发信必须逐次确认；能通过断网/恢复、权限变更、锁定崩溃等测试。

## 阶段 3：扩展与生态（依真实反馈调整）

- 高级 Agent、自动化工作流、插件 API。
- 更多高校平台与通用日历连接器。
- 移动端、跨设备体验、高级项目管理。
- 学习分析、复习算法、外观/小组件、丰富的统计。

## 建议的质量与使用指标

- 学校平台连接成功率、同步准确性、重复项比例。
- 邮件事项提取准确率、误创建率、邮件授权与同步成功率、重复发信事故数（目标为零）。
- 第一次完成设置的比例、每周活跃率、4 周留存率。
- 平均任务创建耗时、规划采纳率、手工修改率。
- 作业截止前完成率、预计/实际耗时误差。
- 专注退出成功率、崩溃后恢复成功率（安全相关指标必须达到严格阈值）。
- 跨平台缺陷数、端到端核心流程测试通过率。

## 阶段执行规则

1. 每个功能单独确定负责人、输入、输出、验收标准和风险。
2. 不把功能“已在 API 文档中出现”误写成“已经获得实际访问权限”。
3. Windows/macOS 都通过核心功能自动测试后才允许合并；涉及系统权限的功能须有真实设备验证。
4. 严格自律功能未经安全审查与异常恢复测试不得面向普通用户开放。
