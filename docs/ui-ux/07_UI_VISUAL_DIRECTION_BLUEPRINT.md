# Study Anchor · UI 视觉落地蓝图

> 本文把「Calm Productivity / Personal Workspace / Minimal & Warm」转化为可直接用于 UI 实施与 Vibe Coding 的页面布局和组件视觉约定。它不改变 W2 已确认的信息架构、交互规则或 P0 功能范围。

## 1. 产品视觉关键词

**安静、清晰、轻盈、专注、个人感。**

Study Anchor 不应像企业管理后台，也不应像过度装饰的 AI 工具。它应当像一个每天会打开、能长期沉淀学习与生活事务的桌面工作空间。界面优先让用户感受到「我知道现在在哪、要做什么、信息来自哪里」，而不是「这个软件有很多功能」。

### 应避免的视觉套路
- 每个内容都包成独立白色卡片，导致卡片套卡片。
- 页面顶部堆叠多行标题、统计数字和重复说明。
- 蓝紫色渐变、玻璃效果、重阴影、过度发光的 AI 元素。
- 将所有模块都设计成相同的三列 Dashboard。
- 仅用红/绿/橙颜色表达状态，缺少文本、图标或可读提示。
- 大面积 Emoji 作为产品图标；不同线宽/风格图标混用。

## 2. 全局框架：混合工作空间 C 的视觉落地

保留既有左侧导航 + 顶部工具栏 + 主内容 + 可折叠右侧上下文栏结构。视觉优化不重新发明导航。

### 左侧 Sidebar
- 视觉上轻于主内容：背景与主画布接近，但通过微弱分界或层次区分，不做重色块。
- 品牌区高度适中；品牌标识简洁、无夸张渐变和浮雕阴影。
- 空间切换器作为一个清晰但不抢眼的入口；个人/团队/AI 项目空间名称与当前空间状态明确。
- 一级模块保持稳定的图标 + 标签组合。当前项用浅色 Accent 背景、文字/图标颜色和细微标识表达，不使用大面积高饱和色。
- 模块分组标题可弱化，但导航标签始终可读。
- 设置、账户和底部工具与主导航分开；窄窗口时可折叠为图标栏，但提供可辨识 Tooltip。

### Topbar
- 高度稳定、视觉轻量；左侧面包屑/当前模块，右侧搜索、创建、通知、上下文栏开关。
- 快捷创建以一个明确的主按钮呈现，其他操作用图标按钮。
- 搜索框不应占据过大视觉面积；默认提示文字简短。
- 不重复显示 Sidebar 已明确的模块名称、Workspace 名称和页面标题。

### Main Content
- 使用统一内容宽度和左右 padding；页面标题、简短描述、主操作在同一视觉层级体系中。
- 内容允许列表、时间线、阅读区、画布等不同形式，不强制套卡片。
- 主操作通常只保留一个突出按钮；次级操作以低强调按钮、文本操作或菜单形式呈现。
- 大区块之间通过间距、标题、轻分隔组织，不使用多层边框。

### Context Panel
- 可折叠，开启时宽度稳定；与主内容以低对比边界区分。
- 展示当前选中对象的详情、来源、时间、证据和操作。
- 未选中时显示简短引导，不保留上一对象的敏感信息。
- 内容变化应跟随当前对象，避免面板自身变成第二个完整业务页面。

## 3. 统一组件的视觉规则

### 按钮
- Primary：低饱和 Accent 实色，文字清晰；仅用于页面最主要的确认/创建动作。
- Secondary：轻背景或描边，不与 Primary 竞争。
- Tertiary：文字或图标按钮，适合取消、返回、辅助操作。
- Danger：仅用于删除、撤销不可恢复等高风险动作；需确认并清楚说明影响。
- Hover：轻微背景变化；不要使用大幅缩放、发光。
- Disabled：降低强调但保持可辨识；如有原因，用辅助文字说明。
- Loading：保留按钮宽度与动作语义，明确正在执行，避免重复提交。

### 输入与选择
- Input、Textarea、Select 的边界、圆角、背景、Focus 状态统一。
- Focus 使用清晰的描边/外环；不要仅改变颜色且对比不足。
- Placeholder 不代替字段标签；重要字段保留显式 label。
- 错误提示贴近字段，并指出可修复原因。

### Panel / Card
- 卡片只在内容确实需要独立分组、选择或操作时使用。
- Panel 默认无重阴影；边框与背景层次轻。
- 列表项优先采用整行交互、轻 hover 和选中态，而不是每项单独的厚边框卡片。
- 卡片标题与操作按钮保持统一的 baseline/对齐。

### Badge / Status
- Badge 适合短状态，如「待确认」「同步中」「已完成」。
- 状态至少由颜色 + 文本共同表达；关键状态必要时加图标。
- 状态样式全局一致，不在每个模块自行定义含义。

### Dialog / Drawer / Toast
- Dialog 用于需要用户停下来确认的动作；内容简短，明确影响和主次按钮。
- Drawer 适合查看详情、编辑上下文，不替代复杂完整页面。
- Toast 仅用于短暂结果反馈，不承载错误恢复说明；重要失败应留在页面。
- 所有弹层需支持键盘焦点、Esc 关闭（除不可中断流程）及明确关闭入口。

## 4. 页面视觉布局蓝图

### 4.1 个人工作台 Overview
目标：用户打开应用后，不需要浏览多个卡片就知道今天的重点。

建议顺序：
1. 日期/轻问候 + 今日重点（简短、不过度个性化）。
2. 今日时间线或近期课程/任务，作为页面视觉主焦点。
3. 待处理区：待确认事项、即将截止、团队待验收等，按紧迫性而非来源模块分组。
4. 快捷开始专注或创建任务。
5. 低频统计、历史或可定制组件放在次级区域或折叠区。

避免：大面积 KPI 数字、重复展示任务数量、多个同权重卡片、未经数据验证的示例数据。摘要条目点击应进入来源模块/原对象。

### 4.2 日历与任务
- 日历视图是页面主结构，不被装饰卡片挤压。
- 日期选择与日/周/月切换放在稳定工具区域。
- 课程、固定事件、个人任务、任务执行块、AI 候选必须有不同但克制的视觉样式；提供图例或文本说明。
- 任务截止日期显示为截止属性；执行时间块显示为安排属性，二者不可混为一谈。
- 选中日期、当前时间线、已完成、冲突、待确认等层级清晰。
- 右侧详情可以编辑/查看来源，但主日历仍是焦点。

### 4.3 知识库
- 优先采用可持续阅读的布局：资料导航/搜索 + 内容阅读区 + 可选详情/AI 辅助区域。
- 阅读区宽度和行长适合长文本；原文与 AI 解释、引用、用户笔记应通过标签/分区/轻边界区分。
- 搜索结果突出命中词和来源，不使用过多统计卡片。
- 导入/解析/索引状态在对应文件附近显示；失败时保留重试与原文件访问。
- 引用可定位到原文页码、段落或时间戳；来源信息不应隐藏在多级弹窗。

### 4.4 知识图谱
- 节点数量、关系线和标签密度应可控；默认不展示所有复杂关系。
- 过滤、缩放、选中和来源详情作为主要操作。
- 已确认、AI 待核验、人工创建的关系样式保持稳定；颜色之外需有状态标识。
- 选中节点后详情优先展示关系解释和证据，避免只显示概念名称。

### 4.5 专注与自律
- 计时器是视觉中心；数字清楚、无装饰干扰。
- 开始、暂停、继续、结束的操作状态明确，关键按钮不随布局跳动。
- 任务名称、专注模式、剩余时间是主要信息；积分、历史、奖励属于次级。
- 正在计时状态不依赖动画表达；暂停、结束、保存、失败均有明确文字反馈。

### 4.6 小组协作
- 项目名称、成员与当前项目状态作为页面识别区。
- 任务列表/看板、讨论和资料之间有明确导航；避免每个模块全部铺在一个长页面。
- 待认领、进行中、待验收、已完成、已退回使用统一状态语言。
- 个人任务与团队任务的来源/权限区别始终可见，个人工作台展示团队任务时是引用，不复制创建。

### 4.7 AI 规划与工作区
- AI 生成内容与正式内容有视觉区分；候选建议始终可审阅。
- 时间规划候选显示前后变化、冲突、选择状态；用户确认前不改变正式日程。
- AI 项目空间突出目标、当前任务、上下文授权与最近工作，不以“AI”渐变装饰为主。
- 模型状态、权限范围、执行状态和费用/用量（若已有）以简洁但可读的方式呈现。

### 4.8 邮件
- 收件箱采用清晰列表与阅读区；邮件正文优先，AI 摘要/候选事项为辅助。
- 未读、重要、附件、线程和发送状态有统一标识。
- AI 提取出的任务/日历建议始终为候选，不自动创建正式事项。
- 发送前显示发件身份、收件人、抄送、附件和正文；确认动作明确，发送结果真实。

### 4.9 连接器 / 同步
- 连接状态在连接器列表和详情中保持一致。
- 状态文案区分「未连接」「需要授权」「已授权」「同步中」「同步完成」「同步失败」「需要重新授权」等真实状态。
- 最近同步时间、授权范围、可撤回操作和失败恢复路径可查。
- 不以绿色点或装饰图标暗示已连接；不隐藏权限范围。

## 5. 主题与状态

### Light
- 暖白/浅米灰 Canvas。
- 面板与画布微弱区分。
- 主文字为深暖灰；次级信息为中性灰。
- Accent 低饱和灰绿，避免整块页面被 Accent 填满。

### Dark
- 深灰绿/暖黑背景，避免纯黑。
- Surface 与 Canvas 保持层次，文字对比足够。
- Accent 在深色环境适当提高亮度，但不高饱和荧光。
- 边界、状态和 hover 不能因深色主题而消失。

### 状态视觉
所有模块共用状态语义：Idle、Loading、Empty、Error、Offline、Permission Required、Pending、Syncing、Success、Unknown。Success 仅在真实操作返回成功后显示；Unknown 不得伪装为 Success。重要状态提供文本和恢复操作。

## 6. 页面改造前后检查

每次改造至少对照：
- 主要焦点是否更明确？
- 页面是否减少重复标题、卡片和装饰？
- 主操作是否唯一、清晰且容易找到？
- 长文本、时间信息和密集列表是否仍然舒适？
- 状态是否真实、可读、可恢复？
- Light/Dark 是否同样完整？
- 窄窗口是否可操作，入口是否保留？
- 原有功能、数据、权限与流程是否没有变化？

## 7. 第一轮 UI Foundation 推荐实施

首轮不直接改所有模块。优先完成：
1. CSS Tokens：Canvas、Surface、Ink、Muted、Border、Accent、Semantic Colors。
2. Sidebar：品牌、空间切换、一级导航、当前态、底部设置。
3. Topbar：面包屑、搜索、快捷创建、通知、Context Panel toggle。
4. 主内容区：统一标题、描述、操作区域和宽度/间距。
5. 共享组件：按钮、输入、Badge、Panel、分隔、状态、空态。
6. Light/Dark theme。
7. 1280px 左右桌面基线与窄窗口折叠测试；具体断点按真实窗口校准。

第一轮结束后再选择 Overview 作为视觉样板页，之后按日历、知识库、专注、协作、AI、邮件、连接器逐模块推进。每个阶段只改明确的文件，先阅读代码，完成后运行类型检查/测试/构建并进行截图回归。

## 8. 与现有 W2 文档的关系

本蓝图只负责视觉方向与布局建议。下列文件继续作为对应权威：
- `01_IA_AND_PAGES.md`：页面、导航与信息架构。
- `02_INTERACTION_DECISIONS.md`：交互规则与用户确认边界。
- `03_MODULE_JOURNEYS.md`：模块旅程与异常恢复。
- `04_STATES_AND_PERMISSIONS.md`：状态、权限、跨平台约束。
- `05_W2_ACCEPTANCE.md`：设计原型体验验收。

若视觉建议与上述规范、PRD、架构或安全约束冲突，以现有权威规范为准，并先提出冲突供确认，不通过 UI 设计绕过业务规则。


## 2026-11-25 · 与已合并 V0.1 工作台及邮件/AI 集成的视觉兼容说明

- 当前 `main` 的首页主体由 `src/renderer/src/Workbench.tsx` 与作用域样式 `workbench.css` 实现八组件聚合、显隐、排序及三套预设。旧版 `App.tsx` 中仅含今日待办的 `overview-workspace` 参考画面**不应覆盖这一真实实现**。本 PR 合并时保留新版 `App.tsx`，由通用设计 token 和组件样式与新工作台自然融合。
- `AIWorkspace.tsx` 现支持 OpenAI、Anthropic、Gemini、DeepSeek 与用户指定的兼容服务商；**不能**把发送目标、Key 来源、模型或计费告知回退为旧版只支持 OpenAI 的文字。视觉只添加阶段标签、布局类名及状态辅助说明。
- `CampusMail.tsx` 已支持用户逐封授权、纯文本正文预览与独立 AI 调用确认；邮件视图的可见确认标签不代表自动读取正文、自动发信或上传附件。
- `CloudWorkspace.tsx` 必须同时保留新版授权撤销/本机历史清理、加密缓存、Cursor 过期重建及补拉状态。视觉分栏不许恢复原来的“明文缓存”错误文案，也不能删掉安全清理按钮。
- 目前 `src/renderer/src/styles.css` 的 Calm Productivity 全局 token 是审美基线；`workbench.css` 继续作为工作台作用域样式，不迁移真实数据逻辑或多模块状态到演示 UI。两套 CSS 均需在 Windows/macOS 真实窗口复测浅/深主题、布局操作和键盘焦点。
- 本次只对旧版可兼容的 UI 调整做合并，不删减日历任务、同步、知识、团队、Canvas 或邮件的新功能。合并成功与 CI 通过不等于视觉 GUI 的人工验收。
