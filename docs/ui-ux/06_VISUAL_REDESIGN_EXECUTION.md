# Study Anchor · UI 视觉改造与实施边界

> 本文是 W2 UI/UX 交互规范的视觉与工程实施补充，不替代 PRD、W2 信息架构或交互决策。改造以现有仓库为基线，逐步改善视觉系统、页面层级与操作体验；不得以 UI 重构为由擅自删减、重写或改变既有业务行为。

## 1. 改造目标

- **Calm Productivity**：降低视觉噪声，让用户快速理解时间、任务、资料与下一步行动。
- **Personal Workspace**：塑造属于用户的学习工作空间，而非传统后台或指标堆叠的 Dashboard。
- **Minimal & Warm**：简洁、克制、温和有质感；避免过冷科技蓝、重阴影、过度玻璃拟态、夸张渐变和 AI 炫技装饰。
- **Hierarchy before decoration**：先处理信息优先级、阅读节奏、空间组织和操作路径，再做装饰。
- **Functional continuity**：视觉不能让用户误认为功能已连接、同步、授权或执行成功。

## 3. 视觉原则

1. **清晰主次**：每页一个主要焦点；主操作、次操作、危险操作层级分明。
2. **低噪声**：减少重复容器、重边框、无意义阴影和高饱和色；不可隐藏必要来源、状态、权限信息。
3. **留白有目的**：使用间距改善阅读，但不牺牲任务/时间信息密度。
4. **暖而不甜腻**：温和中性色为主，可少量使用植物绿、麦色或陶土色；避免幼态化。
5. **全局一致**：同类组件在不同模块保持相同语义、尺寸、反馈和状态。
6. **状态真实**：Loading、Empty、Error、Offline、Permission、Sync、Pending、Unknown 等状态明确；不能仅靠颜色表达。
7. **可访问**：焦点可见、对比度足够、点击区域合理、文本放大不破坏布局、图标有标签。
8. **桌面优先且可折叠**：窄窗口可折叠侧栏/上下文栏，但模块仍可访问。

## 4. Design Tokens（先统一再逐页使用）

所有视觉参数先集中到 CSS Variables/Token，避免组件内散落硬编码。以下是方向而非最终色值，需截图与双主题校准。

| Token | 建议 | 用途 |
| --- | --- | --- |
| Canvas | 暖白、浅米灰 | 页面背景 |
| Surface | 纸白/轻暖灰 | 面板、浮层 |
| Ink | 深暖灰/灰绿黑 | 主文字、保证对比 |
| Muted | 中性灰 | 元信息、辅助说明 |
| Border | 低对比暖灰 | 必要分组与分隔 |
| Accent | 低饱和植物绿/灰绿 | 主操作、选中、链接，克制使用 |
| Accent-soft | 极浅绿灰 | 选中背景、轻提示 |
| Secondary accent | 柔和麦色/陶土色 | 少量特殊强调，不与主色竞争 |
| Success/Warning/Danger | 语义色 | 统一状态，兼顾深色主题与可辨识性 |

**排版**：优先系统字体栈，不增加不必要字体依赖。建立有限的标题、正文、辅助信息、数字和标签层级。减少重复标题和大面积粗体；知识库/邮件正文应优先保证阅读舒适。

**空间与组件**：建立统一间距 scale（可从 4/8/12/16/20/24/32 起校准）；圆角只保留控件、卡片、浮层等有限层级；优先用留白/分组代替全页面卡片化。阴影只用于明确层级。动效短且克制，并尊重系统减少动态效果。

**组件**：统一 Button、Input、Select、Checkbox、Tabs、Panel、Dialog、Toast、Badge、Tooltip、Skeleton、Empty、Error、Status；统一图标来源、线宽、尺寸与对齐，不混用字符图标、Emoji 和多套 SVG 风格。覆盖 hover/focus/pressed/disabled/loading/error，不只设计默认态。

## 5. 实施阶段与页面顺序

保留 W2 已确定的混合工作空间 C：侧栏导航 + 顶栏工具 + 主内容区 + 可折叠上下文详情。

### Phase 0 · UI 审计（只读）
阅读 `App.tsx`、`styles.css`、W2 IA/interaction/state 文档及原型；记录 Layout、导航、路由/页面切换、主题变量、重复组件、窗口约束、状态和数据依赖。保存改造前截图（浅/深主题、核心页面、较窄窗口），列出第一批修改文件。

**交付**：简明审计记录、截图基线、修改文件列表。不在本阶段改源码。

### Phase 1 · Design Tokens + Workspace Shell
统一 Token；调整 Sidebar、Workspace Switcher、顶部工具栏、主内容区和可折叠详情栏；规范共享 UI 组件；保留全部入口与空间切换行为；同时验证 Light/Dark 和窄窗口。

**验收**：视觉统一、当前模块/空间清晰、导航正常、两套主题可读、无入口丢失或功能回归。

### Phase 2 · 个人工作台（视觉样板）
优先今日最重要任务/课程/时间线；其次聚合待确认事项（任务、邮件、复习、协作）并标明来源；提供专注入口；低频统计可折叠/隐藏。避免堆卡片或展示未经验证的示例数据。

**验收**：用户能快速判断下一步；摘要跳转来源模块；组件显隐/排序/尺寸/预设等既有 P0 设计不受损。

### Phase 3 · 日历与任务
改善日/周/月视图一致性、时间线、日期选择和选中层级。课程、固定事件、个人任务、执行时间块、AI 候选需有克制但可辨识的区别。截止日期与执行时间块分离；统一完成、延期、取消、待确认状态。

**验收**：日期/筛选/详情同步；已有创建、编辑、完成、恢复等操作正常；来源、锁定、同步状态可见。不得改动重复课程、时间冲突、同步或任务规则。

### Phase 4 · 知识库与图谱
优先长文阅读、资料列表、导入/解析状态、搜索结果和出处。原文、AI 解释、证据、笔记层级明确。图谱状态（待核验、已确认、人工）有稳定视觉映射，证据可访问。

**验收**：阅读、导入、搜索、引用和定位不回归；待核验内容不能被视觉包装成事实。

### Phase 5 · 专注与自律
计时器作为主焦点；时长预设、自定义、标题、控制和当前状态清晰。Idle/Running/Paused/Finished/Saving/Error 视觉可辨；积分/历史/奖励为次级。严格模式、限制、紧急退出和恢复提示必须准确。

**验收**：计时、保存、历史、积分及安全退出行为不变；无动画干扰计时反馈。

### Phase 6 · 团队、AI、邮件、连接器
按真实完成程度分模块推进，不因 PRD 规划存在就假设已实现。
- 团队：项目、成员、任务、讨论、共享资料与权限边界。
- AI：候选、正式计划、授权范围、模型状态、采纳/撤回分层；建议不冒充执行结果。
- 邮件：列表/线程/阅读/草稿/发送确认一致；发送身份、收件人、附件透明。
- 连接器：未连接、授权中、已连接、同步中、失败、重新授权等状态真实表达。

**验收**：每个改造模块检查既有操作、空/错误状态、权限边界和跨模块跳转；不得伪造同步、连接、发送成功。

## 6. 改造边界（强制执行）

### 默认允许
- `src/renderer/src/styles.css`：全局 Token、视觉样式、布局、响应式与组件样式。
- `src/renderer/src/App.tsx`：仅展示、布局、组件组织、样式挂载等 UI 范围，不能改变既有业务语义。
- `src/renderer/src/*.tsx`：各展示组件的样式、布局与反馈；修改前需阅读组件及直接依赖。
- 新增纯 UI 组件/样式文件：先确认已有组件体系，避免重复；不引入未经批准的依赖。

### 未经明确批准禁止修改
- `src/main/**`、`src/preload/**`、`src/shared/**` 中业务逻辑、IPC、数据模型、数据库、同步与安全边界。
- Canvas/教务/邮箱/日历连接器认证、API、数据映射、同步、重试和来源规则。
- Task/Event/Focus/Knowledge/Workspace 实体状态、校验、权限、业务规则。
- `supabase/**`、SQL、迁移、云端 RLS、数据保留/删除语义。
- `package.json`、`package-lock.json` 依赖或版本修改（需单独提出并获批准）。
- 其他成员负责的模块、尚未审阅的工作或进行中的 PR。
- 删除功能入口、用 Mock 替换真实数据，或伪造连接/发送/同步成功。

### UI 任务触及边界时
暂停越界部分，先说明：①纯 UI 为什么无法完成；②具体文件/逻辑；③影响数据、功能、安全或他人工作的风险；④纯展示替代方案及最小必要修改方案。未经确认不执行。

## 7. AI / Vibe Coding 每轮规范

每轮按顺序：
1. **目标**：页面/组件、用户痛点、预期效果。
2. **现状**：阅读目标文件和直接依赖，确认行为、状态、数据与样式。
3. **计划**：列出拟修改/新增文件，并证明属于 UI 范围。
4. **实施**：局部修改；先 Token/共享组件，再页面应用；避免一次改全站。
5. **自检**：类型检查、相关测试、构建与人工页面验证；无法运行必须标记未验证。
6. **汇报**：文件变更、视觉效果、保留行为、测试结果、风险/未完成项。
7. **下一步**：等待体验反馈或下一页面确认，不擅自扩张到业务逻辑。

每轮开始前明确页面、文件范围、要保留的关键交互，以及是否允许新增 UI 组件。默认最小必要修改；跨模块任务应拆分。

- [ ] 常见桌面窗口与窄窗口可操作，折叠不丢入口。
- [ ] 键盘焦点可见、文本缩放可读、对比度足够、动效克制。
- [ ] Loading/Empty/Error/Offline/Permission/Sync/Pending/Unknown 状态正确。

### 功能回归
- [ ] 工作台聚合数据与源模块一致，跳转正常。
- [ ] 日历视图、日期选择、任务筛选、详情正常。
- [ ] 任务创建/编辑/完成/恢复等现有操作正常。
- [ ] 知识库导入、阅读、搜索、引用/证据展示正常。
- [ ] 图谱关系状态与来源清晰。
- [ ] 专注计时、保存、历史、积分规则不变。
- [ ] 团队、AI 规划、邮件、连接器现有功能与权限提示不回归。
- [ ] 未授权数据不因聚合、搜索或布局调整泄漏。

### 工程边界与验证
- [ ] 改动只落在批准的 UI 文件。
- [ ] 未增加未经确认的依赖。
- [ ] 未改共享数据模型、IPC、数据库、同步或权限逻辑。
- [ ] 无明显 React 状态错误、控制台错误、布局溢出。
- [ ] 已运行可用的 typecheck/test/build，并如实记录。
- [ ] 手工验证改造页面及关联操作；未验证项说明原因。
- [ ] 对比前后截图，确认改善的不仅是换色。

## 9. 首轮建议任务

首轮只做 **UI Foundation + Workspace Shell**，不同时重做全部模块：
1. Light/Dark Design Tokens；
2. 侧栏品牌、导航项、选中态和空间切换器；
3. 顶栏、主内容宽度、全局间距；
4. 统一 Button/Input/Badge/Panel/Divider/Empty/Status；
5. 窄窗口折叠策略（不删入口）；
6. 选取工作台、日历、知识库、专注四页做截图回归。

首轮优先限制在 `styles.css`。若需改 `App.tsx`，先列出 UI 层理由和具体修改范围。全局基准验收后，再进入工作台视觉改造。
