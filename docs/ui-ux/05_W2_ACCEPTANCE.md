# W2-5 · 原型走查、交互验收清单与后续输入

> 状态：W2 设计归档及待最终体验确认的验收记录。完成某个**模拟原型**检查，不意味着 P0 真正实现、接口验收或 OS 真机安全测试通过。所有 P0 开发完成后须另外执行 [PRD E2E-01～15](../PRD.md#11-首版-p0-跨模块端到端验收)。

## 1. 原型及使用方法

- 原型位置：[`prototypes/w2-hybrid-workspace/index.html`](../../prototypes/w2-hybrid-workspace/index.html)。下载后用现代浏览器直接打开；单个 HTML 文件，不依赖后台服务。
- 主界面：左侧工作空间切换器与八模块导航，顶部搜索/新建/通知，中央内容以及可折叠详情栏。
- 点击各业务模块下方的「W2 关键交互走查」卡片进入模拟对话框；可选择修改文字、切换权限、确认/取消等。它会明确声明“仅演示”，绝不会调用真实 Canvas、邮箱、云 AI、操作系统限制或本机文件读取。
- 原型验证的是信息架构与用户决策点，不验证网络 API、数据库持久化、真正邮件发送、跨平台原生限制或 AI 准确度。
- 原型可能尚未实现全部可编辑控件的拖动/持久化、无障碍与长流程回退；**这些功能属于正式 P0 设计要求，不能因为原型演示简化而被降级**。

## 2. 已记录的九项交互审阅结果

| 编号 | 采用方案/落地结论 | 已决定的 P0 行为 | 后续增强 |
| --- | --- | --- | --- |
| 2.1 | C，模块内 + 工作台统一候选 | 来源证据、编辑/接受/忽略，不确认不写正式事项 | 复杂多级自动化 |
| 2.2 | C，团队任务可选审核 | 无审核可完成；开启审核由单负责人批准或退回 | 按任务重要性设置多个审核人/通过人数 P1 |
| 2.3 | C，选择性批量排程 | AI 候选独立、只应用被选时间块、锁定日程不被改动 | 高级重排优化 |
| 2.4 | C，知识边可信分层 | AI 关系待核验、人工确认后正式采纳、证据可追溯 | 高阶关系推理 |
| 2.5 | C，混合掌握度 | 系统建议 + 用户覆盖，最终评价决定间隔复习 | 模拟考试/薄弱点专项 P1 |
| 2.6 | C，轻量/严格专注 | 授权、实际生效说明、紧急退出、异常恢复 | 自适应限制/桌宠 |
| 2.7 | C，邮件范围配置 | 按账号/文件夹分析、用户逐次最终确认发信 | Gmail/Outlook 专用邮箱接入 P1 |
| 2.8 | C，小组默认项目概览 | 概览→任务/讨论/文件/成员，个人任务引用 | 协同编辑/高级分析 |
| 2.9 | B，工作台组件化 | 显隐、排序、基础尺寸、主题/背景、预设和重置 | AI 动态布局/主题市场 |

**布局**：混合工作空间 C 已获用户认可；视觉润色和更多个性化将在后续深化。补充建议（完整页面、首次启动、外部接入、AI 权限、现实奖励、知识分享、文件级同步、异常状态等）已获用户同意并纳入对应章节。

## 3. W2 用户体验检查清单（可逐项手工走查）

| 用例 | 验收动作 | 预期结果/必须看见的交互 |
| --- | --- | --- |
| UX-01 首次启动 | 选择本地开始、跳过 jAccount、再进入连接向导 | 不强制学校账号；已授权与未授权项目分开显示 |
| UX-02 空数据 | 未连接 Canvas 时打开日历 | 显示未连接及手工导入/连接入口，不能伪造真实课表 |
| UX-03 校园接入 | 查看 Canvas、教务、邮箱卡片及可见范围 | 分别授权、显示实际同步状态与错误原因；后续真实验收另做 |
| UX-04 候选中心 | 从邮件生成事件候选，不接受就退出 | 不创建正式事项；保留来源、冲突和修改入口 |
| UX-05 时间块 | 在三条 AI 建议中只勾选两条 | 只应用选中两条；锁定课程和作业截止不变；可以撤销 |
| UX-06 文件导入 | 选 PDF、PPT、录音、Vault，检查进度 | 各文件有解析/OCR/ASR 及失败恢复状态，原件不丢 |
| UX-07 可信问答 | 点击 AI 回答引用、打开来源 | 无源时标“无依据”；来源真实才可跳转；原型示例出处有明确虚构标记 |
| UX-08 图谱 | 查看一条 AI 待核验边和人工已确认边 | 样式区分、可核验/拒绝，跨文档证据双向跳转 |
| UX-09 自动复习 | 用户把系统建议「熟练」改「困难」 | 最终评价可保存、下次复习安排基于最终选择 |
| UX-10 AI 项目 | 只授权一个目录，关掉云 AI 外传 | 查看明确范围/排除子目录，越界拒绝；外传不能继承读权 |
| UX-11 专注 | 进入严格模式、模拟权限拒绝与紧急退出 | 有授权和白名单预览；显示降级与安全退出；真机恢复测试另做 |
| UX-12 奖励 | 创建现实奖励并尝试兑换 | 名称/积分/记录可追溯；无自动现实购买 |
| UX-13 团队任务 | 提交需验收的成果，切换到审核人 | 待验收而非已完成；可批准/退回，有意见和历史 |
| UX-14 多人验收扩展 | 在团队任务设置查看审核规则 | P0 允许单人；多审核人和票数明确标 P1，不误认为已实现 |
| UX-15 私人知识共享 | 选择特定文档/知识节点，分享给组 | 明确接收者、权限与撤权；未选私人资料不能被自动共享 |
| UX-16 邮件范围 | 对某邮箱文件夹关闭 AI 分析 | 后续该范围不参与分析；用户能看到生效范围 |
| UX-17 邮件草稿 | 新建/回复全部后修改收件人和附件 | 最终确认显示全部地址、内容与附件；无确认不发送 |
| UX-18 发信未知 | 模拟发送 API 超时 | 进入待核验；先查远端，不自动重复发送 |
| UX-19 逐文件同步 | PDF A 选上传、录音 B 选仅本机 | 每个文件独立控制；未选 B 不会上传，跨设备需按需获取 |
| UX-20 离线冲突 | 两设备修改一篇笔记后恢复联网 | 可查看差异、选择版本或保留两份，不静默覆盖 |
| UX-21 工作台外观 | 隐藏复习组件、改变主题和排序后重启 | 用户布局可恢复、背景不默认上传、可重置默认 |
| UX-22 快捷搜索/托盘 | Ctrl/⌘+K、托盘打开下一事项 | 搜索按权限筛选，失效通知权限有应用内替代入口 |
| UX-23 角色/撤权 | 退出团队或撤销项目授权后访问旧链接 | 新访问必须拒绝，既有可导出数据的处理规则清晰 |
| UX-24 跨平台 | Windows 与 Mac 使用相同流程及不同快捷键 | 主要语义一致，OS 专有权限/菜单栏/文件路径明确区分 |

上表是**设计验收标准**，不是宣称 HTML 已覆盖所有 24 条的真实执行。需要在正式功能上线前把每条拆为自动化或真人操作测试，并区分：原型可展示、功能已实现、真实服务已验证、双平台真机已通过。
