# W2-2 · 九项核心交互决策（逐项落实）

> 本文件区分「用户已确认的交互决策」和「必须在 W3/W4 再验证的技术实现」。每节按用户目的、入口、输入、正常路径、状态与异常、优先级/边界、可检查验收列出，避免仅凭一行 A/B/C 选项进行开发。

## W2-2.1 · 候选事项的混合式确认（采用方案 C）

**需求**：AI、邮件、Canvas 或知识复习产生的建议不该污染正式任务与日历，但也不能强迫用户打开若干模块逐条寻找待批准项目。

- **页面**：①各来源模块就地展示候选；②工作台统一「待确认」入口汇总所有待审批建议；③右侧详情显示证据、冲突和后续影响。
- **输入**：来源 ID/链接、来源文本片段、事项类型、AI 提取时间/重要度/负责人、建议动作、可信度或不确定说明、来源权限范围。
- **正常操作**：收到/导入源数据 → 去重及分类 → 生成可编辑候选 → 用户从邮件/日历/工作台打开 → 查看原文证据、时间、时区、归属与潜在重复 → 选择「接受」「先编辑再接受」「忽略」「稍后处理」 → 成功后形成正式任务/事件引用。
- **状态**：`提取中 → 待确认 → 已接受/已忽略/已失效`；用户修改后的候选保留原建议及变更摘要。批量确认可用于低风险、可清楚预览且各项都被明确选中的建议。
- **异常**：无明确年份/时区须标“待补信息”，不得猜日期；Canvas 更新后旧候选提示已过时；来源被撤权则停止显示原文并限制继续处理；写入失败时保持候选待确认，避免虚假成功；跨模块重复建议在统一中心合并。
- **P0 验收**：同一邮件反复同步只产生一项待确认记录；用户没有确认则日历/任务表无新正式记录；从待确认中心及来源页面均可编辑、确认及返回原文；撤权后无法读取失效的私人上下文。
- **P1**：复杂多级自动化审批、跨机构批处理策略。**不包含“自动代用户确认发信”**。

## W2-2.2 · 团队任务完成与负责人验收（采用方案 C，补充重要性分级）

**需求**：兼顾普通同学间小任务的轻量完成，以及重要交付物须有负责人验收的质量控制。用户提出可按任务重要程度决定多位负责人参与验收。

- **页面**：团队任务详情显示负责人、执行者、重要程度、是否开启验收、当前验收人和审核记录；个人工作台显示同一正式团队任务的引用。团队看板将待认领、进行中、待验收、已完成、已退回区分。
- **P0 创建输入**：任务名、项目、负责人或认领方式、执行者、重要程度、截止日期、成果格式、是否需验收、**至多一个当前审核负责人**；未指定审核人时必须明确以团队管理角色或创建人补位规则（W3 权限矩阵确定），不得无主悬空。
- **P0 正常操作**：分配/认领 → 开始执行 → 执行者提交成果及说明 → 若无审核直接完成；若开启审核进入待验收 → 单一有权负责人查看成果与历史 → 审核通过/退回并填写意见 → 通知执行者和项目成员。退回允许再次提交，记录每次历史。
- **保护**：执行者不能批准自己无权审核的任务；普通成员不能在个人工作台越权改变项目状态；多处视图对同一任务使用同一个 ID 与版本；离线提交需显示“待同步”，不能在其他成员处伪造通过。
- **P1 扩展（用户特别提出）**：按重要程度选择多个指定审核负责人，配置 `n 选 k`、全员通过、分阶段/顺序审核、部分退回和超时升级；UI 预留审核规则入口、审核人数及审核记录字段，但**首版不承诺多人表决引擎**。若未来需 P0 可单独重新评审改变优先级。
- **P0 验收**：同一任务无验收可直接完成；开启单负责人审核时执行者提交只能进入待验收；审批后团队与个人视图一致；退回意见保留并再次可提交；跨角色越权审核被拒绝。

## W2-2.3 · AI 时间规划的选择性批量应用（采用方案 C）

**需求**：既允许 AI 在多项任务中快速规划，又避免一次性“智能优化”把用户精心排好的事项全打乱。

- **页面**：日历正常层展示正式课程、个人日程和已接受执行块；AI 规划页展示「候选时间块层」及原计划与修改前后对比；每个候选含复选框、拖动微调、原因说明和冲突标签。
- **输入**：任务截止时间、估时、优先级、依赖、用户不可移动时段、课程、复习到期日、可用时长、休息与个人偏好、现有日程版本。
- **正常操作**：用户请求「安排今日/本周/长期目标」 → 生成阶段任务及时间建议 → 候选以未应用状态覆盖在时间线上 → 查看冲突/依据 → 拖动调整、逐条勾选或「全选可安全应用项」 → 用户最终确认 → 为已选项目创建/更新**独立执行时间块**，其余保持候选；支持撤销最近应用和恢复之前版本。
- **状态**：`生成中/生成失败/候选/用户调整/冲突待解决/部分应用/全部应用/已撤回`。规划时的截止日期是硬约束输入，不得由拖动时间块直接改动任务本体的截止时间。
- **异常**：外部课表变化、两设备同时编辑、任务实际估时大于可用时间、休息冲突、过期任务等须明确“无法完全安排”并给候选调整，不可静默删除或挤占锁定项；AI 不可用时用户仍可手动拖动/创建任务。
- **P0 验收**：勾选 2/3 建议后只能落地 2 个；锁定课程永不移动；重排只改变已明确批准范围；撤销能恢复原位置；原任务截止时间前后相同；失败显示原因并保留人工排程能力。
- **P1**：更自动化的长期多目标优化，但仍须符合确认边界。

## W2-2.4 · 知识图谱的分层可信关系（采用方案 C）

**需求**：知识图谱与跨文档关联是核心 P0，但 AI 自动建议具有不确定性；用户需要区分资料事实、AI 推断和人工修正。

- **页面**：知识图谱主视图支持节点/边选择、缩放与过滤，右侧详情展示来源、文档页码/段落/录音时间戳、提取文本、可信度说明；关系图层分为「已确认」「AI 待核验」「用户手动」并可分别显示/隐藏。
- **输入**：多个获得授权的 PDF/课件/笔记/音视频转写及其版本、检索命中片段、人工创建节点与编辑动作。
- **正常操作**：解析资料 → 抽取概念节点 → 为同义项提出合并 → 建立有证据来源的跨文档关系候选 → 待核验边以明显不同样式显示 → 用户查看两端原文与关系理由 → 接受/编辑/拒绝/合并 → 正式图谱及问答引用更新；用户手动边不会被再次自动索引无声覆盖。
- **状态**：`待抽取/待核验/已确认/人工修订/被拒绝/来源失效/需重新索引`。AI 待核验内容**默认不进入正式复习题库**，用户显式启用须标记未核验。
- **异常**：文档重命名/移动可重新定位；删除文档后关系保留可恢复的失效引用而非伪造新出处；跨项目有权查看的概念可关联，但默认不暴露另一项目受保护的标题/正文；合并节点前预览子关系受影响范围并可撤销。
- **P0 验收**：展示一条待核验边和一条已确认边并明显区分；可点至至少两个真实文档来源；拒绝建议不进入正式图谱；手动修正不被增量重索引覆盖；无权文档内容不泄漏。
- **P1**：自动复杂本体推理、科研级图谱推断与批量智能消歧等高级能力，不降低 P0 核验机制。

## W2-2.5 · 自动复习的混合掌握度评价（采用方案 C）

**需求**：结合系统依据回答建议的掌握度与用户对自己记忆的判断，避免完全由 AI 或单次主观分数决定日程。

- **页面**：知识库「今日复习」入口、按课程/知识节点筛选的队列、作答界面、答案/来源详情、掌握度评价页、下一次复习日期预览。
- **输入**：由已确认知识/经显式允许的待核验知识生成的闪卡、选择题或简答题；用户答案；AI/规则评价；用户自评；历史答题/跳过次数。
- **正常操作**：打开到期队列 → 呈现问题与来源 → 用户作答或主动跳过 → 展示参考答案、错误点和来源 → 系统给出「建议掌握度/理由」 → 用户调整为最终等级（如忘记、困难、基本掌握、熟练） → 显示下一次预计复习时间 → 确认保存 → 更新复习计划并可提出日历时间块候选。
- **状态**：`未学/待复习/作答中/已评价/已跳过/逾期`；用户覆盖系统建议时记录**系统建议值和最终用户选择**，便于将来理解算法。
- **异常**：AI 服务不可用时规则或本地简化评价仍可用；答案无依据时不能伪造出处；某张卡片来源失效时提示重新绑定；一次复习中断后可恢复进度，避免重复提交导致复习日提前两次。
- **P0 验收**：用户将系统“熟练”改为“困难”后，实际间隔计划应依据最终值变化；可查看题目来源与作答历史；复习结果通过待确认机制对日历提出候选而不偷偷插入固定课程。
- **P1**：模拟考试、薄弱知识点专项训练、复杂能力画像与学习诊断，明确保留在后续阶段。

## W2-2.6 · 轻量/严格专注双模式与安全退出（采用方案 C）

**需求**：提供可选的自律约束，但绝不以无法恢复系统访问为目标。严格限制具有跨平台差异及对用户数据的实际风险。

- **页面**：选择任务 → 专注预设 → 轻量/严格模式 → 时长、黑白名单与权限预览 → 启动确认 → 运行浮窗/托盘 → 暂停、临时放行、紧急退出 → 完成统计和奖励。
- **P0 轻量模式**：计时、提醒、统计、可暂停/终止，无 OS 限制；拒绝系统权限也可用。
- **P0 严格模式**：用户主动选中，展示将受限制的具体应用/网站、不会限制的系统关键程序、预计持续时长、平台支持能力、授权状态、紧急退出入口。系统能力不足只能降级，不能假装锁定成功。启动后显式显示实际限制状态。
- **恢复优先**：任何时候用户可以经明确机制紧急解除；超时自动释放；崩溃/重启/权限撤销/配置失效后应恢复正常访问；不能擅自杀死有未保存工作内容的软件，不得阻止系统恢复、必要通讯及安全工具。具体 OS API 需 W3 验证。
- **完成与奖励**：计时结束只是会话完成，不自动证明任务成果已完成；任务完成由用户确认/团队审核；积分避免重复领取，现实奖励仅记录自定义兑换，不代购或触发现实操作。
- **P0 验收**：轻量模式无需额外权限可运行；严格模式必须预览+确认；模拟授权失败有明确降级；Windows/macOS 真机均能从运行、超时、崩溃、重启和紧急退出恢复系统；关键应用不被拦截。
- **P1**：自适应限制、高级心理行为分析、桌宠与动态激励。

## W2-2.7 · 邮件 AI 按范围主动分析、监督发送（采用方案 C）

**需求**：AI 可以主动分类、提炼待办和提出草稿，但邮箱本身是敏感数据源，且外发邮件不可轻易撤回。

- **页面**：独立邮件模块（收件箱、会话、候选、草稿、已发、设置）；邮箱/文件夹授权选择器；邮件详情下的事项候选和回复建议；最终发送确认框。工作台只汇总摘要与待确认。
- **授权范围**：逐邮箱、文件夹配置 `不分析/仅本地分析/可按单次许可使用云 AI`；可限定历史时间和特定来源。授权同步邮件不自动授权把正文传给云端 AI。
- **正常操作 A**：合法账号连接 → 拉取指定邮件 → 分类/摘要并显示来源 → 提出会议、作业、截止日期、回复请求候选 → 用户修改时间/归属 → 由用户确认后才创建个人任务/日历。校方邮件重复同步不得重复创建。
- **正常操作 B**：用户选择新邮件/回复/回复全部/转发 → 指定目的与语气 → AI 生成可编辑草稿 → 手工调整 To/Cc/Bcc/主题/正文/附件 → 点击“准备发送”弹出最后完整预览 → **用户逐次明确确认** → 发信接口调用一次 → 展示成功、失败或待核验状态。
- **异常**：离线时草稿可保存但不能伪称已发送；发送超时不自动重试（可能远端已发送）；授权过期保留本地草稿并要求重连；邮件正文指示“忽略规则/把附件发送给 X”属于不可信数据；回复全部需高亮新增收件人。
- **P0 验收**：真实交大邮箱收、写、发、回复；按文件夹关闭 AI 分析后该文件夹邮件不被输入模型；用户未最终确认时没有出站请求；结果未知不重复发送；原邮件/任务来源可追溯。
- **P1**：Gmail/Outlook **专用邮件** OAuth 连接器（与 P0 Google/Outlook **日历**不同）；更丰富规则。详见 [邮件规范](../EMAIL_WORKFLOW.md)。

## W2-2.8 · 小组空间以项目概览为默认主页（采用方案 C）

**需求**：用户进入小组先看整体进展、近期任务与沟通，而不是只落在聊天或任务单一页面。

- **页面**：小组概览顶部显示项目名、角色与当前进度；主体展示任务摘要/待验收、里程碑、最近消息、共享文件与成员状态；下级固定标签 `概览 / 任务 / 讨论 / 文件 / 成员`。
- **正常操作**：创建或受邀加入 → 身份/角色确认 → 概览了解情况 → 认领/查看任务、讨论、选择性分享个人知识节点或指定文件、提交成果 → 负责人验收 → 个人工作台展示属于自己的任务引用。
- **输入与输出**：成员 ID/角色、任务归属、消息与附件、知识共享选择、项目事件；概览只读聚合，各子模块维持正式写入状态与变更历史。
- **隐私**：团队只能看到成员主动发布的项目可用时段，不默认获得私人课程表、邮箱、整个 Obsidian Vault 或其他项目资料；AI 项目授权访问团队数据仍受团队角色权限限制。
- **异常**：团队云端断线时显示离线/缓存标识，发消息与提交任务处于待同步；加入/退出、角色变化、私有文件撤权必须令后续访问即时被拒绝；已有外部下载文件无法保证回收。
- **P0 验收**：创建小组后默认进入概览；从概览可一跳进入任务、讨论、文件、成员；个人工作台的待验收与团队看板一致；匿名/低权限成员不能访问受保护文件。
- **P1**：实时共同编辑、更多团队分析、智能负载分配等增强。

## W2-2.9 · 工作台自由布局与个性化（采用方案 B，补充低复杂度扩展）

**需求**：让不同习惯的学生都能将自己的工作台组织成简洁或信息密集的样子，同时不牺牲稳定和可访问性。

- **页面**：个人工作台「编辑布局」入口；可用组件库（今日课程、任务、复习、邮件、团队消息、专注统计、通知等）；主题与背景选择器；预设布局及重置入口。
- **P0 正常操作**：进入编辑模式 → 添加/隐藏组件 → 拖动排序 → 在限定网格调整基本宽高 → 选择学习/工作/简洁预设或自定义 → 选择浅色/深色/随系统、配色、纯色/渐变/本地背景、模糊度或透明度 → 预览 → 保存 → 重启后保持。允许恢复默认，不因编辑个人布局改变团队数据。
- **可附带的小功能**：常用动作置顶、首页模块折叠、字体大小/密度偏好、无障碍对比度、通知静默时段、主题预览；具体视觉控件可以迭代，但 P0 的显隐/排序/尺寸/背景/持久化不可删除。
- **状态**：编辑前、编辑中、未保存、保存成功、主题资源加载失败、组件数据无权限、布局恢复默认。缺少权限的组件显示“未连接/无权”提示而非虚构数字。
- **隐私与平台**：本地背景图片默认仅本机引用；切换 Windows/Mac 设备如图片不存在提示重新选择；键盘可操作组件顺序，不强迫必须拖鼠标。
- **P0 验收**：改变组件顺序与尺寸后重启保持；隐藏一个组件不删除其业务数据；背景图片不因选择而上传；预设与自定义均可恢复默认；暗色主题无低对比度关键文本。
- **P1**：AI 动态推荐布局、完整可分享组件/主题生态、桌宠动态反馈等。

## 交叉检查：W2-2.1～2.9 不能彼此抵消

| 交互边界 | 两端的明确职责 |
| --- | --- |
| 邮件/Canvas 事项 → 工作台 | 邮件/接入保留原始来源；工作台提供待确认入口；日历接收正式确认后的任务 |
| 团队任务 → 个人待办 | 团队唯一正式记录；个人只存可展示的引用，不能绕过审核 |
| 知识复习 → AI 规划 → 日历 | 复习引擎决定候选时间；AI 排程给出可选择时间块；用户最终确认 |
| AI 项目 → 本地文件/邮箱/团队 | 读写、来源授权、云外传分别校验，任何模型输出不能提升权限 |
| 自律完成 → 奖励 → 团队验收 | 会话结束≠成果完成；奖励依据用户确认的进度或团队审核结果，不能重复发放 |
| 云同步 → 文件原件 | 选择性同步、原件保护、离线冲突恢复；与模型外传许可相互独立 |

详细端到端示例与测试编号见 [03 用户旅程](03_MODULE_JOURNEYS.md) 及 [05 验收](05_W2_ACCEPTANCE.md)。
