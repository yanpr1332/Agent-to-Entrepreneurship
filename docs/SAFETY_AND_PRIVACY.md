# 安全、隐私与责任边界（规划稿）

> 本文是工程安全需求和讨论草案，不是法律意见，也不能替代正式用户协议、隐私政策或法律审查。

## 为什么专注限制属于高风险模块

应用/网站限制可能导致紧急通信受阻、必要软件打不开、工作中断、通知错过或系统操作受影响。软件必须避免依赖“不可关闭、不可绕过”作为产品卖点。

## 专注功能必需的安全保护

1. 默认关闭限制功能；仅用户主动启用并明确授权后才执行。
2. 启动前明确展示目标程序/网站、限制时长、恢复方式和已配置白名单。
3. 必须保留紧急退出；不得限制系统安全、无障碍、必要通信与紧急使用功能。
4. 设置会话最长时长；超时自动解除。
5. 应用崩溃、系统重启、权限撤销、配置损坏时以**恢复正常访问**为优先原则。
6. 不得窃取系统权限、修改系统安全组件、阻止任务管理器/强制退出或篡改系统恢复机制。
7. 对支持程度低的平台仅提供可安全实现的功能；界面如实提示限制效果及可绕过性。
8. 对高风险状态进行必要的本地日志记录，日志不应包含浏览或学习内容等不必要的敏感信息。
9. 针对 Windows 和 macOS 各自验证：正常开启、超时、提前退出、崩溃、断网、重启、权限变化。

## 数据与身份保护

- 尽量本地存储；云同步为用户可选择的功能。
- OAuth Token 使用系统安全存储，提供断开授权、范围说明与清除入口；不保存学校账号密码。
- 个人日历、学习资料和原始录音默认仅本人可见，团队共享须单独授权。
- 云端文件、索引、聊天和任务受角色权限控制，禁止跨租户/跨项目越权读取。
- 对 LLM/ASR 云服务传输数据之前说明处理范围并征得用户许可；支持关闭 AI 和云上传。
- 邮箱只读权限与写入/发送权限应分开申请，用户能按账号和文件夹控制同步范围；邮件正文、联系人与附件不得未经授权进入云端模型或团队空间。
- AI 可拟写邮件、提出回复或发送建议，但绝不自动对外发送。每次发送前必须展示并要求确认发件账号、To/Cc/Bcc、主题、正文、附件、回复/转发对象；用户可随时编辑或取消。
- 邮件内容可能包含恶意提示或诱导指令，应作为不可信数据处理，不能因此改变权限、发送给第三方、泄露私人资料或跨账户操作。
- 发送接口超时或结果未知时不得盲目重试，须先核验发送状态，防止重复邮件。发送失败、授权撤销和附件缺失应明确提示。
- 支持导出、删除、备份和恢复，明确缓存及日志的处理方式。
- 对课程录音、受版权保护的课件和个人信息遵守适用法律及学校规定。

## AI 项目授权与文件级云同步（P0）

- 按项目配置文件、目录、子目录排除范围、知识库、邮箱、日历、团队空间或 Git 仓库的数据访问；默认只读，可选择单次、会话、定时或持续授权并随时撤销。
- 权限由程序执行层校验，而不只是把“不要越权”写进提示词；不得通过上级路径、链接或间接调用绕过项目作用域。
- AI 有权本地读取，不代表允许发送完整文件或片段到云模型。用户应能区分本地推理、云端推理以及数据是否外传。
- 大型原始资料默认不上传，用户可以逐个文件授权云同步或从同步范围移除。同步开关、停止同步和删除已上传的云端副本应有明确区别。
- 云端同步数据应加密传输和保存；是否采取端到端加密，以及团队共享与搜索兼容方式，留待 W3 细化。
- Windows/macOS 本地目录应分别明确授权，不因为另一设备具有同名项目就自动赋予本机文件夹访问权。

## 许可证和最终用户条款不是一回事

项目采用 MPL-2.0。其第 6、7 节分别包含无担保和责任限制条款，但它主要处理代码授权，不保证对所有最终用户使用行为都能免责。用户协议、应用内风险提示、隐私政策、显式授权和实际安全措施必须另外设计。

- 官方许可证：https://www.mozilla.org/en-US/MPL/2.0/
- 特别注意：不同司法辖区可能限制免责条款的效力；发布前应获得适用地区专业法律意见。

## 专注模式界面警示语（待法律与可用性审查）

> 严格专注模式可能临时影响部分应用或网站的使用。请检查允许列表，并确认已了解退出方式。该功能仅用于自愿时间管理，不保证能够完全阻止分心行为，不能作为安全、医疗或应急控制工具。遇到紧急情况时，用户可通过明确提供的紧急退出机制解除限制。依法不得排除或限制的责任不受本提示影响。

## 其他失败场景

- **漏提醒/错期**：学校 API、时区、缓存和离线状态可能造成误差；显示数据来源和最近同步状态，允许多种提醒与用户检查。
- **AI 幻觉/错误规划**：以建议呈现，标注依据、允许撤回；不得悄悄替代用户决策。
- **团队误共享**：最小权限，确认共享对象，保留变更历史与撤销能力。
- **邮件误发/错发**：AI 草稿只能供审阅；发送确认与实际调用分离，对收件人地址、抄送、附件及线程执行最终核对；保留不包含不必要敏感正文的审计记录。
- **原始数据丢失**：不应默默覆盖文档，支持版本历史、备份、恢复与导出。

## 安全发布门槛

严格模式、安全权限、账号令牌、共享授权等未通过测试时，不得在正式版中启用相应功能。应制定漏洞报告和应急响应机制，见仓库根目录 `SECURITY.md`。
