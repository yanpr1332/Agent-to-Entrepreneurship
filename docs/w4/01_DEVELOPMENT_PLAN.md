# W4-01 开发计划与 V0.1 内部 Alpha 范围

## 1. 交付目标
**目标日期：2026-11-25。** 交付 Agent-to-Entrepreneurship V0.1 内部 Alpha：
- Windows 和 macOS 均有可运行的桌面测试版本。
- 五名团队成员使用各自账号，通过互联网进入同一共享工作空间。
- 八大模块均有入口和可演示的基础能力。
- 个人数据可本地保存，关闭并重新打开应用后仍可恢复。
- 团队任务与消息可在不同设备之间真实同步。
- Canvas 能使用真实账户读取课程/作业等授权数据。
- 交大邮箱能真实收件，并在用户逐次确认后真实发送测试邮件。
- 知识库能导入资料、建立可追溯的知识关系并运行基础自动复习。
- AI 能在用户授权的上下文中生成建议，只有用户确认后才写入正式任务。

这是限期内部原型目标，不承诺完整正式 P0 产品在 11 月 25 日全部交付。此前对完整正式 P0 产品的粗略人周估算，不应用来推导本次短周期 Alpha 的可行性；本计划以可演示闭环和硬性验收门槛管理风险。

## 2. 与正式 PRD 的关系
- 八大模块正式 P0/P1/P2 划分继续以 docs/PRD.md 为唯一产品优先级依据。
- 内部 Alpha 选择每个模块的最小真实闭环，是交付节奏安排，不是修改 PRD 优先级。
- Canvas 真实读取与交大邮箱真实收发为用户明确强调的 Alpha 必交付项。
- SJTU 教务 API、Google Calendar、Outlook Calendar、Notion 等其他正式 P0 接入仍保留在正式 P0 路线中；其授权验证并行推进，不能用 ICS 或模拟数据宣称已完成这些连接器。
- 复杂双向同步、完整离线冲突解决、高级 AI Agent、模拟考试、桌宠、应用商店发布不作为本次 Alpha 的必要条件，除非 PRD 的硬性安全边界要求。

## 3. 原型技术基线
| 层级 | 计划基线 | 状态 |
|---|---|---|
| 桌面容器 | Electron | W3 已选 |
| 前端 | React + TypeScript | W3 已选 |
| 本地数据 | SQLite，Local-first | W3 已选 |
| UI | 沿用 W2 混合工作空间，基础组件优先 | 实现细节可调整但保持 W2 结构 |
| 云端协作 | 先验证 Supabase；通过后用于 Alpha 团队空间 | 候选，尚未通过验证 |
| AI | 可替换 Provider；每位用户独立配置/授权 | Provider 与密钥管理需验证 |
| 外部接入 | 统一 Connector Engine + Canvas Adapter + IMAP/SMTP Adapter | W3 设计基线 |
| 构建 | Windows 与 macOS 内部测试包 | 需真实设备验证 |
| 代码协作 | GitHub feature branch + Pull Request | W4 采用 |

不得因为原型赶工而取消 Electron 主进程/Preload/Renderer 隔离、系统凭据存储、服务端 RLS、邮件逐次确认或 AI 数据外传授权。

## 4. 八大模块 Alpha 最小闭环

### M1 个人日程与任务
- 本地任务创建、编辑、完成、删除和持久化。
- 任务优先级、截止日期、备注和状态。
- 日历/列表至少一种清晰的日期视图，优先完成日历视图。
- ICS 导入/导出。
- Canvas 作业可经来源映射进入个人任务；保留外部 ID、来源链接和同步时间。
- 远端更新不能覆盖用户个人备注、完成状态和自定义字段。

### M2 个人知识库
- 导入 PDF、Markdown、TXT；原始文件默认留在本机。
- 提取文本并建立本地可搜索索引。
- 创建知识节点，并允许用户手动建立/编辑关系。
- 支持跨文档关联，关系能够追溯到来源文档/片段；AI 推荐关系标记待确认。
- 能查看基础知识图谱。
- 能由知识内容创建闪卡并完成一次复习。
- 复习后依据用户最终评价生成下一次复习时间。高级语义检索与完整 FSRS 优化可后续增强，但图谱、跨文档关联和自动复习不能退化为静态占位页。

### M3 专注与奖励
- 专注计时器可开始、暂停、结束。
- 保存专注记录。
- 完成记录后按规则生成积分，防止重复领取。
- 显示基础统计和积分余额。
- Alpha 不要求启用高风险严格系统限制；任何已实现限制都必须可紧急退出和安全恢复。

### M4 团队协作
- 五个独立用户账号。
- 创建/加入同一共享工作空间。
- 成员列表与最小角色权限。
- 团队任务创建、编辑、指派、状态更新。
- 团队消息发送与接收。
- 不同设备上的更新可被其他成员看到。
- 个人知识、邮件和本地原始文件不因加入团队而自动共享。

### M5 AI 辅助规划
- 至少接入一个真实可用的模型 Provider。
- AI 对话和任务建议。
- 用户明确选择文件/知识作为上下文。
- AI 生成结构化候选任务或日程建议。
- 用户预览、修改并确认后才能写入 M1。
- 每位用户独立配置模型密钥；密钥不进入 Git、普通数据库或提示词。

### M6 数据接入与扩展
- 连接器管理入口可添加、测试、查看状态和断开连接。
- Canvas 用户可配置实例地址。
- Canvas 个人 Token 仅用于开发者本人本地验证。
- OAuth 作为五人多用户接入目标，需学校/Canvas 管理员 Developer Key。
- 真实读取课程、作业、截止时间；如权限允许，读取日历事件。
- 支持分页、去重、来源追踪、同步状态与撤权。
- ICS 导入导出是开放格式能力，不冒充 Canvas/Google/Outlook API 接入。

### M7 邮件管理与 AI 通信
- 独立邮件模块，不把邮件中心塞进个人工作台。
- 通用 IMAP/SMTP 账户配置，优先验证上海交通大学邮箱。
- 真实读取收件箱并查看邮件正文。
- 创建、保存和编辑邮件/回复草稿。
- 发送前展示发件账号、收件人、抄送/密送、主题、正文、附件和回复对象。
- 每次实际发送均由用户逐次确认。
- 发送超时状态未知时先核验，不盲目重发。
- AI 可从用户明确授权分析的邮件中提取任务/会议候选；用户确认后写入 M1。
- 邮件原文默认不上传团队云端，不默认发送给云端 AI。

### M8 个人工作台
- 沿用 W2 混合工作空间导航。
- 显示今日任务、日历、复习、专注和团队动态等基础组件。
- 支持基础组件显隐/排序或预设布局。
- 支持浅色/深色主题。
- 工作台只做聚合入口；邮件中心仍是独立模块。

## 5. 数据边界
| 数据类别 | Alpha 默认位置 | 共享/外传规则 |
|---|---|---|
| 个人任务、日历、知识原件、专注记录 | 本地 SQLite/本地文件 | 只有明确选择后才同步/共享 |
| 团队工作空间、共享任务、团队消息 | 云端团队空间 | 服务端 RLS 按成员/角色隔离 |
| Canvas Token / OAuth Token | Windows Credential Manager 或 macOS Keychain 等系统凭据存储 | 不写普通数据库、GitHub、团队云端或 AI 上下文 |
| 邮箱凭据 | 系统凭据存储 | 不上传云端 |
| 邮件正文/附件 | 默认本地 | AI 读取需独立授权；团队共享需另行选择 |
| AI API Key | 用户本机安全配置 | 不提交仓库，不写日志，不进入团队共享表 |
| PDF/录音等大文件 | 默认本地 | 逐文件选择云同步；不因索引/图谱生成自动上传原件 |

## 6. 方案边界与失败处理
- Supabase 验证失败时，暂停依赖其实现的多人实时协作开发，评估可替换方案；不临时自建复杂后端来掩盖失败。
- Canvas Developer Key 未及时获批时，可用开发者本人 Token 证明单人真实 API 读取，但必须标记 OAuth/五人独立授权未通过；不得共享个人 Token，也不得宣称五人 Canvas 接入已验收。
- 交大邮箱认证方式或 SMTP 权限不允许时，记录真实阻塞并持续验证；不能以模拟邮件通过验收。
- 某平台无合法授权时，不绕过学校或服务商访问控制。
- 任何 P0/Alpha 门槛受阻，明确标记阻塞和影响，不得静默降级。

## 7. 不在本次目标内
应用商店发布、公开商业化、完整自动更新、所有服务商邮箱兼容、复杂多人协同编辑、全部第三方双向同步、完整云端原件存储、完整正式产品安全认证均不属于 11 月 25 日内部 Alpha 的前提条件；它们是否属于正式 P0/P1 仍按 PRD 和 W3 决策执行。
