## 关键路径
1. Windows/macOS 最小启动 → Electron 工程骨架 → 本地数据和凭据层。
2. Supabase PoC → Auth/Workspace/RLS → 团队任务与消息 → 五人 E2E。
3. 联系学校申请 Developer Key 与开发者个人 Token 验证并行 → Canvas Adapter → 课程/作业读取 → M1 映射。
4. 交大邮箱 IMAP/SMTP 认证 Spike → 邮件连接器 → 收件/草稿/逐次确认发送 → 邮件转任务。
5. SQLite/导入索引 → 知识节点/关系 → 图谱 → 闪卡/复习调度。
6. AI Provider → 授权上下文 → 候选任务 → 用户确认写入。
7. 两平台持续构建与测试，不把跨平台验证留到最后一天。

## 每日管理节奏
- 每次工作开始前，用简短异步记录说明今天准备完成的 Task ID、依赖和可能冲突。
- 任务开始时在 GitHub Issue 中认领临时 Driver/Reviewer 和文件范围。
- 每天至少一次集成检查：主开发分支/候选分支能否启动，新增测试是否通过。
- 遇到外部审批、凭据或设备阻塞，当天记录，不等待里程碑才报告。
- 每个里程碑结束后根据验收证据更新状态和剩余风险。

## 日期风险处理
- Developer Key 审批可能超出团队控制；申请应尽早提交并持续跟进。
- 邮箱第三方客户端认证可能受学校策略影响；必须先验证真实测试账户。
- macOS 测试设备、芯片/系统版本或安全提示可能影响安装；提前完成最小包测试。
- Supabase PoC 若不通过，立即记录原因并评估替代方案；不在最后阶段临时重写云端后端。
- 任何 Blocker/Critical 都必须明确标记；若 11 月 25 日未达到 Alpha 门槛，应交付真实状态和可运行的已完成部分，不得伪造验收。

## 里程碑后的工作
11 月 25 日后，根据真实缺陷、外部授权状态和团队时间制定下一轮迭代计划。正式产品仍需完成 PRD 所有 P0、W3 风险门禁和完整发布验收。
