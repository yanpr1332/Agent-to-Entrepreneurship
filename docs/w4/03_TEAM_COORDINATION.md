# W4-03 团队协作与责任边界

## 1. 团队现实条件
团队共有五名学生，成员时间受学业影响，技术基础不要求完全相同。AI 编程工具承担主要代码生产和重复工程工作，人类负责需求判断、任务边界、授权、运行环境、真实账号、代码审查和验收。

本计划**不把五个人固定绑定到五个永久岗位，也不预先把每项任务分配给某个具体成员**。任何成员都可以根据当周时间和能力认领一个或多个任务；任务可交接，但交接必须更新 Issue/PR 记录。

## 2. 责任域（不是固定人员岗位）
| 责任域 | 工作范围 | 不负责/边界 |
|---|---|---|
| 产品与需求 | PRD 对齐、用户流程、验收场景、范围变更记录 | 不绕过技术接口修改其他模块实现 |
| 桌面框架与体验 | Electron 主窗口、导航、React 页面、可访问性、Windows/macOS 体验 | 不自行更改领域数据模型或服务端权限 |
| 本地业务与知识 | M1/M2/M3 本地任务、知识、图谱、复习、专注 | 不直接调用第三方平台 SDK；通过 Connector/AI Port |
| 外部连接器与邮件 | Canvas、IMAP/SMTP、连接状态、邮件领域流程、外部来源追踪 | 不自行决定团队云端数据权限或修改 M1 表结构 |
| 云端协作与同步 | Auth、Workspace、团队任务/消息、RLS、同步边界 | 不上传个人邮件/原始知识文件或个人 Token |
| AI 与质量 | AI Provider、上下文授权、候选动作、测试、跨平台回归 | AI 不拥有隐含写入、发信或云端外传权限 |

责任域可以由同一人跨域承担，也可以多人协作；每项任务最终只有一个临时 Driver 对交付负责。

## 3. 每项任务的最小责任记录
在 GitHub Issue/PR 中至少记录：
1. Task ID：对应 W4_DEV_BACKLOG 的唯一编号。
2. Driver：当前执行负责人，任务结束或交接时更新。
3. Reviewer：不同于 Driver 的复核者；高风险任务由熟悉安全/集成的人复核。
4. Acceptance：由谁/按何种步骤验收，可由产品代表或真实环境使用者承担。
5. Scope：允许修改的目录、文件和公开接口。
6. Dependencies：依赖的 Task ID、服务授权、设备或账号。
7. Evidence：测试命令、截图、日志、录屏或脱敏响应。
8. Handoff：交接时说明已完成、未完成、风险、分支和下一步。

不得把用户名、账号、真实凭据、学生隐私或邮件正文放入公开 Issue/PR。

## 4. 防止重复与冲突的规则
- 开始任务前先搜索 Task ID、开放 Issue 和进行中的 PR，避免重复实现。
- 同一文件不得被两个 Agent/成员同时修改；必要时先确定一个 Driver 或拆成不重叠文件。
- 公共接口、DTO、数据库迁移、权限策略和共享 UI 组件是高冲突区，先提出变更再并行实现。
- 每个模块拥有自己的领域逻辑和数据写入权；跨模块调用公开 Port 或发布领域事件。
- 不允许直接写入其他模块的私有表；不得通过前端绕过服务端 RLS。
- 外部连接器只负责认证、请求、分页、限流、错误、来源 ID 和同步游标；M1/M2/M7 负责各自业务映射。
- AI Agent 的工作范围必须写明允许修改路径和禁止修改路径。
- 完成后尽快提交小 PR；不要长期积累大范围未合并改动。

## 5. 建议目录责任边界
| 目录（计划结构） | 主要责任 | 变更约束 |
|---|---|---|
| apps/desktop | Electron Main、Preload、Renderer 启动与窗口 | Main/Preload 安全变更需额外复核 |
| packages/contracts | DTO、IPC Schema、领域事件 | 公共契约变更需先讨论并通知调用方 |
| packages/core | 用户、工作空间、权限、公共原语 | 高冲突区；需要架构复核 |
| packages/modules/m1-calendar | 日历与任务 | 只写 M1 自有数据；跨模块走 Port |
| packages/modules/m2-knowledge | 资料、图谱、复习 | 来源权限继承；不得默认共享原件 |
| packages/modules/m3-focus | 专注、奖励 | 系统限制需单独安全评审 |
| packages/modules/m4-collaboration | 团队空间、聊天、共享任务 | 服务端 RBAC/RLS 必须生效 |
| packages/modules/m5-ai-planning | AI 规划和候选动作 | 不直接绕过用户确认写业务数据 |
| packages/modules/m6-connectors | Connector Engine 和 Adapter | 不包含邮件业务 UI/草稿规则 |
| packages/modules/m7-email | 邮件收件、草稿、事项提取、确认发送 | 每次发信独立确认 |
| packages/modules/m8-dashboard | 工作台聚合与偏好 | 不成为其他模块的领域数据源 |
| packages/ai-runtime | 模型 Provider、工具授权执行 | 模型 Key 与上下文权限隔离 |
| packages/sync | 本地 Outbox、云同步和冲突 | 按文件同步；权限撤销可核验 |
| packages/system-adapters | Windows/macOS 原生能力 | 每个 OS 单独验证 |
| tests | 单元、集成、E2E、安全与夹具 | 测试数据必须脱敏/合成 |
| docs | PRD、W2、W3、W4 及开发记录 | 决策和实现状态保持同步 |

以上是 W3 规划目录，不表示本次已创建代码目录。

## 6. 交接与冲突解决
- 任务 Driver 退出或无法继续时，在 Issue 更新当前状态、分支、改动文件、测试结果和剩余风险，再由新 Driver 接手。
- 两个 PR 修改同一公共接口时，暂停其中一个，先合并接口决策或重新拆分。
- 需求与技术冲突时，不能由 AI 自行决定删除 P0；提出影响并交由用户确认。
- 发现安全风险时可以阻止合并，不因 11 月 25 日日期而绕过安全门槛。
