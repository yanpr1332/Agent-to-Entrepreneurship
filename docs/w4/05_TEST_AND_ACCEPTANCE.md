# W4-05 测试与验收体系

## 1. 验收原则
- 以 PRD 功能编号、W2 UX 编号、W3 风险编号和 W4 Task ID 建立追踪关系。
- “代码存在”“页面可打开”“Mock 返回成功”都不等于功能通过。
- Canvas 和交大邮箱必须有真实账号/真实数据证据。
- 五人协作必须使用五个独立账号和不同设备/网络环境测试。
- Windows 与 macOS 分别验收，不能以一个系统的结果替代另一个系统。
- 安全门槛失败时不得为了日期而绕过。
- 测试证据应脱敏，不在公开仓库保存真实 Token、邮件正文、学生个人数据或受限课程资料。

## 2. 测试层级
| 层级 | 内容 | 证据 |
|---|---|---|
| T1 单元测试 | 任务状态、日期/时区、去重、积分账本、复习调度、权限判断 | 测试报告 |
| T2 集成测试 | SQLite、模块 Port、Connector Adapter、AI Runtime、云端 API、RLS | 测试报告与脱敏日志 |
| T3 桌面 E2E | 首启、导航、任务、知识、复习、专注、AI、邮件确认、工作台 | 录屏/截图/测试结果 |
| T4 真实外部环境 | Canvas、交大邮箱、五人云端协作 | 测试账户类型、脱敏响应、时间和结果 |
| T5 双平台与恢复 | Windows/macOS 启动、安装、更新、断网、重启、凭据存取 | OS/版本/芯片、日志、复现步骤 |
| T6 安全与权限 | Token 泄漏、RLS 越权、AI 外传授权、邮件逐次确认、撤权 | 安全测试用例与结果 |

## 4. 关键端到端场景
### E2E-A：Canvas 作业进入个人任务
1. 开发者使用自己的本地 Token 或已获批 OAuth 账户连接 Canvas。
2. 读取真实课程和作业。
3. 显示作业名称、课程、截止时间、来源链接。
4. 用户选择导入后生成个人任务。
5. 再次同步不重复创建。
6. Canvas 更新截止日期时不覆盖用户备注和个人完成状态。

### E2E-B：真实邮件转任务
1. 用户配置交大邮箱 IMAP/SMTP。
2. 获取真实邮件并打开正文。
3. 用户明确选择允许 AI 分析该邮件。
4. AI 提出任务/会议候选并引用邮件来源。
5. 用户修改、接受或忽略。
6. 只有接受的候选才写入 M1。

### E2E-C：监督发送邮件
1. 用户新建或选择回复草稿。
2. 系统显示发件账号、To/Cc/Bcc、主题、正文、附件和线程。
3. 用户明确确认本次发送。
4. SMTP 发送真实测试邮件。
5. 接收端核验。
6. 若超时则进入 unknown 并先核验，不自动重发。

### E2E-D：五人团队协作
1. 五名成员使用不同账号登录。
2. 进入同一 Workspace。
3. 成员 A 创建共享任务。
4. 成员 B 更新状态。
5. 成员 C/D/E 看到一致状态。
6. 成员发送消息，其他成员收到。
7. 非成员尝试访问时被服务端拒绝。

### E2E-E：知识图谱与复习
1. 导入两份不同资料。
2. 建立知识节点并关联两份资料。
3. 查看关系证据。
4. 创建闪卡并完成复习。
5. 用户提交掌握度。
6. 系统生成下一次复习日期并持久化。

## 5. 缺陷分级
- Blocker：应用无法启动、数据丢失、越权、凭据泄露、未经确认发信、Canvas/邮件核心真实接入完全失败。
- Critical：核心闭环无法完成、跨用户数据混淆、同步覆盖个人数据、双平台一方无法使用。
- Major：核心操作有明显错误但有安全可行的临时绕行。
- Minor：视觉、文案或非关键交互问题。

Blocker/Critical 未解决不得标记 Alpha Ready。安全问题不能以“内部原型”为由豁免。
