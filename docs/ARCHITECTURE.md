# 技术架构与数据模型（草案）

**设计输入**：[PRD V1.0](PRD.md) 的八大模块均为首版 P0。本文件仍属 W3 前的技术候选，不代表数据表、API 或技术栈已定稿；需对照功能编号完成模块接口与数据字典。

## 候选技术栈

| 层级 | 候选 | 目的 |
| --- | --- | --- |
| 桌面容器 | Tauri 2 | Windows/macOS 共用一套应用框架 |
| 用户界面 | React + TypeScript | 页面、交互与共享状态 |
| 本地原生与核心 | Rust | 系统适配、任务调度、文件/数据库操作 |
| 本地结构化数据 | SQLite | 离线任务、日历、索引元数据和同步队列 |
| 服务端 API（选型待定） | FastAPI（候选） | 独立账号、跨设备云同步、团队协作与连接器支持 |
| 云数据库（选型待定） | PostgreSQL（候选） | 团队、成员、权限及同步数据 |
| 文件 | 本地文件 + 对象存储 | 个人资料及授权共享的团队附件 |
| 实时协作 | WebSocket | 消息、任务状态与在线更新 |
| 知识检索 | 全文检索 + 向量索引候选 | P0 精确/语义搜索、跨文档关联与可溯源问答 |
| 图谱与复习 | 本地知识节点/关系、复习调度器 | P0 可编辑图谱、关联依据、复习状态和日历联动 |
| AI 权限 | 项目作用域与读写/外传许可执行层 | 文件夹级授权，按用户、项目、操作及本地/云端目的地校验 |
| 音频任务 | 可选本地/服务端 ASR worker | Whisper/FunASR、FFmpeg，不依赖 WSL |

这仅是首选方案，须通过小型技术验证确认跨平台打包、性能、依赖体积和安全性。

## 分层原则

1. **领域层**：任务、课程、日历、资料、项目、专注、规划、邮件与通信；不依赖平台 API。
2. **应用层**：导入、去重、任务调度、提醒策略、规划算法、权限校验。
3. **平台适配**：Windows/macOS 分别实现通知、文件权限、托盘、快捷键和自律限制。
4. **连接器**：Canvas、SJTU、ICS、邮箱提供商、Obsidian、ASR、LLM，均可替换/关闭；连接器不负责邮件模块的完整 UI 与业务决策。
5. **服务端协作能力**：账号、跨设备同步、共享项目、聊天及文件分发为 P0 需求；具体托管方式仍待 W3 选择。个人资料本地优先且可离线。

## 统一实体

- `User`：用户偏好、授权、个人设备。
- `Course`：学期、教学班、教师、排课、外部标识。
- `Event`：固定日程/可调整工作时段，位置、参与人、重复规则。
- `Task`：标题、预计时长、优先级、截止时间、执行时间、负责人、依赖、状态。
- `Resource`：原始文件、路径、哈希、类型、课程/项目归属、访问权限。
- `KnowledgeItem`：笔记、引用、出处定位、标签、知识关联。
- `KnowledgeNode` / `KnowledgeEdge`：知识图谱节点、关系、来源证据、生成/手工修订标记。
- `ReviewCard` / `ReviewAttempt` / `ReviewSchedule`：闪卡/练习、答题结果、掌握度、复习间隔及日历关联。
- `FocusSession`：模式、关联任务、实际时长、退出/中断。
- `Project` / `Membership`：团队、角色、共享范围、协作任务。
- `TeamMessage` / `SharedResource` / `TaskReview`：聊天、附件、选择性知识共享、任务验收/退回。
- `AIWorkspace` / `DataGrant` / `ActionGrant`：项目上下文、文件/文件夹和外部数据源授权、有效期、操作权限、本地与云端 AI 目的地。
- `RewardLedger` / `CustomReward`：积分增减与现实奖励兑换记录。
- `PlanSuggestion`：建议时段、依据、版本、采纳/否决/撤回历史。
- `ExternalBinding`：外部平台 ID、同步状态、来源、最近修改时间、权限与冲突记录。
- `Device` / `SyncSelection` / `SyncConflict`：设备、逐文件云同步选择、远程占位和冲突/恢复状态。
- `DashboardLayout` / `ThemePreference`：自定义工作台组件、布局与主题背景。
- `EmailAccount`：邮箱供应商、授权范围、同步配置和状态；敏感令牌存放在操作系统安全存储中。
- `EmailMessage` / `EmailThread`：来源邮箱、原始邮件/线程标识、时间、发件人、收件人和受控内容缓存。
- `MailActionProposal`：从邮件提取的任务/日历建议、来源片段、去重键及用户采纳记录。
- `EmailDraft` / `MailSendAttempt`：编辑中的草稿、关联线程、发送账号、收件人列表、人工确认记录、接口返回状态与防重试标记。

## 邮件模块边界

- **独立业务模块**：邮件中心、账户列表、收件箱与线程、分类、邮件事项候选、草稿编辑、AI 拟写、人工确认发送及发送状态。
- **数据接入模块**：仅提供邮箱供应商的认证、读取、草稿及发信协议适配。
- **个人工作台**：仅聚合未读/待处理摘要与快捷入口，不承载完整邮件客户端。
- **日历与任务模块**：用户确认后接收邮件事项，保留原邮件引用和去重键。

## 数据同步规则（设计目标）

- 个人本地创建的事项：本地为首要编辑端，离线修改入队，联网后同步。
- Canvas/学校课表：默认**只读导入**，保留来源标识，不能覆盖用户自己的私人字段。
- Google/Outlook 日历及 Notion：首版 OAuth 授权后只读同步所选范围，保留来源 ID 和映射；更复杂的双向编辑留 P1。
- 团队任务：以共享空间权限为准；个人规划器只能安排自己的执行时间。
- 所有同步必须防止重复、记录来源与最近状态，检测冲突并允许人工处理。
- 邮件正文原则上只在用户选择的范围处理；邮件派生的任务可独立保存，但保留可访问的来源引用。邮件读取授权不自动意味着发送授权。
- 附件分开存储，团队共享须显式授权；索引不应越权检索其他人的私人资料。
- 跨设备同步需用户可选，**大型 PDF/录音/视频原件按单个文件授权上传**，支持批量选择但可单独覆盖；不默认同步所有原件，不等同于 AI 云端读取授权。
- 离线修改应缓存为待同步变更；冲突保留可恢复版本，并明确停止同步与删除云端副本的区别。

## AI 边界

核心日历、任务、提醒和数据读写必须在 AI 不可用时继续工作。AI 负责理解与建议；高影响操作（发邮件或回复、共享、删除、群发、改变团队时间）需明确确认。检索问答返回出处，不能把模型推测当作课程事实。邮件正文、附件和引用内容属于不可信输入，不能授予模型额外权限。

AI 可以使用用户自备 Key 和本地模型，项目方托管体验额度不属于首版硬性要求。所有 AI 工具访问应验证“用户现有权限 ∩ 项目数据授权 ∩ 当前操作许可”，默认只读；文件路径/符号链接等不能绕开范围。开启个人云同步不自动开启向云端模型外传数据。

## 开发组织建议

统一仓库（monorepo）可在真正启动编码时使用：

```text
apps/desktop/          Tauri + React 应用
packages/core/         领域模型与共享逻辑
packages/connectors/   学校、日历、笔记平台连接器
crates/platform/       Windows/macOS 原生适配接口
services/api/          可选云端 API
services/workers/      可选文件解析与 ASR 任务
docs/                  需求、架构、决策、安全与验收
```

目录结构仅为建议，尚未初始化任何代码工程。
