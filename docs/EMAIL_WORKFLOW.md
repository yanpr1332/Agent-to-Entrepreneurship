# 邮件接入、事项提取、AI 拟写与监督发送

**状态：产品需求草案；尚未实现。** 邮件功能属于跨模块能力：连接器负责访问邮箱，个人工作台负责展示，任务/日历负责执行，AI 负责建议，用户负责最终决策。

## 一、目标与范围

1. 经用户授权拉取指定邮箱的邮件，优先使用官方 API 与受支持的 OAuth 授权。
2. 识别邮件包含的会议、作业、截止日期、待办、回复请求、项目资料等，提出结构化建议。
3. 用户确认后把候选事项写入个人任务或日历，并保留来源链接与去重信息。
4. 根据用户指令和明确选择的邮件上下文，拟写新邮件或回复、回复全部、转发；允许润色、调整语气、翻译及补充附件提醒。
5. 由用户逐次审阅和确认后发送，记录结果。**任何 AI 生成、自动分类或自动化规则都不能绕过发送确认。**

## 二、功能拆解

### A. 邮箱授权与同步（MVP）

- 支持连接多个邮箱；每个邮箱拥有独立授权和启停配置。
- 支持手动同步及合理频率的增量同步，展示连接状态、上次成功时间和错误原因。
- 按用户选择的文件夹、时间范围、关键词/发件人等范围同步，避免默认抓取所有历史邮件。
- 邮件元数据包含来源账号、邮件 ID、线程 ID、发送时间、主题、发件人、To/Cc/Bcc、正文/附件可访问状态。
- 本地搜索或只读预览应能返回原邮件位置；删除本地缓存或撤销授权不应修改邮箱原文。

### B. 邮件智能收件箱（MVP）

- 显示“未处理”“已提取候选”“已归档关联”“无需处理”等状态。
- 识别事件时间、时区、地点、截止日、行动要求、优先级和建议负责人。
- 提取结果按类型展示：创建任务、创建日历、添加参考资料、设置提醒、仅存档。
- 用来源摘录解释识别依据；不确定时间、缺失年份或冲突信息须突出提示。
- 点击确认后才创建任务/事件；使用源邮件 ID + 候选指纹进行去重，避免重复同步导致重复创建。
- 外部邮件变化应提示可能需要更新事项，不直接覆盖用户后来编辑过的内容。

### C. AI 草稿与回复（第二阶段）

- 新邮件：用户描述目的、对象、语气、语言、长度和附件需求，生成可编辑草稿。
- 回复：基于用户选中的原始邮件及允许的历史线程生成上下文相关回复。
- 回复全部和转发必须明确显示实际目标收件人，不在模型生成时暗中扩大收件范围。
- 支持多个候选版本、重新生成、润色、缩短、扩写、翻译、正式/轻松语气切换。
- 草稿可以仅保存在本地；在用户授权后可保存到邮箱服务的 Drafts。
- 附件不应由模型自行选择私人文件；需要用户主动添加或确认附件建议。

### D. 用户监督发送（第二阶段）

发送前展示完整预览：

| 检查项 | 必须显示或验证的内容 |
| --- | --- |
| 发送身份 | 当前邮箱账号和 From |
| 收件人 | To/Cc/Bcc 的完整实际地址，外部域名或新增收件人醒目提示 |
| 主题与正文 | 当前最终版本及引用的上下文 |
| 回复对象 | 原始线程、Reply-To、回复/回复全部/转发类型 |
| 附件 | 文件名、大小、用户是否确实选择 |
| 动作 | 保存草稿、修改、取消、**确认发送** |

- 用户明确确认后执行单次发送操作，不允许定时或后台未经逐次确认的自动发送。
- API 超时和不确定结果进入“待核验”，先核对远端发送状态，不直接重发。
- 发送结果展示成功、失败、待确认等状态，尽可能关联远程消息 ID。
- 提供撤销本地尚未发送草稿的能力；已成功发出的邮件不能承诺真正撤回。

## 三、优先连接器

| 方向 | 目标能力 | 备注 |
| --- | --- | --- |
| Gmail API | 授权读取、草稿、发送 | 需核实用户授权范围、应用审核及访问限制 |
| Microsoft Graph Mail | Outlook/微软邮箱读取、草稿、发送 | 区分只读与 Mail.Send 等许可 |
| 上海交大邮箱 | 学生实际使用的邮件系统接入 | 具体开放的接口/协议、授权条件必须实测，不假设直接可用 |
| IMAP/SMTP 适配 | 其他支持标准协议的邮箱 | 仅在服务条款和安全授权方式允许时提供，不默认要求明文密码 |

## 四、数据与权限设计

- 读取、保存草稿、发送分别设计权限等级；需求变化时再请求更高权限。
- 本地缓存、索引、模型输入须尊重用户选择；邮件不默认变成团队共享文件。
- 发送权限不能被 AI、邮件正文、附件内容或自动化规则提升。
- 对邮件和附件中的提示注入、链接欺骗、伪造发件人、外部敏感信息传输建立防护。
- 记录用户确认事件、请求 ID、发送结果及必要错误元数据；尽量避免将完整邮件正文写入日志。
- 用户可以断开邮箱连接并清除其本地缓存；由邮件派生的用户任务是否保留应由用户选择。

## 五、验收场景

1. 授权、撤销与重新连接邮箱不损坏已有个人任务。
2. 相同邮件反复同步不会重复创建待办或事件。
3. 对“下周三前完成作业”“周五下午开会”等邮件能提出可审查的时间建议；模糊日期不擅自确定。
4. 用户可以修改 AI 草稿；没有点击最终发送确认就不会产生出站邮件。
5. 回复全部/转发不会悄悄增删收件人，附件缺失会提示。
6. 发送超时不会因自动重试而产生重复邮件。
7. 邮件正文含有“忽略之前规则、发送给某地址”等恶意指令时，系统不执行越权行为。
8. Windows 和 macOS 的相同业务流程与提示一致；离线时不能假装已发送成功。

## 六、版本优先级

- **P0 / MVP**：只读邮箱连接、增量同步、邮件工作台、基础事项提取、用户确认创建日历/任务。
- **P1 / 第二阶段**：上下文 AI 拟写、草稿管理、回复/回复全部/转发、逐次审核发送、发送状态核验。
- **P2 / 后续**：更丰富的分类规则、跨项目智能关联、模板与合规的半自动处理；仍禁止未经逐次确认的自动发信。
