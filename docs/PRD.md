# 产品需求文档（PRD）V1.0

**需求状态：W1 已完成集中审阅并经用户确认（2026-11-04）。W2（2026-11-05）已将页面层级、九项交互方案、用户旅程和异常状态详尽归档；W2 详细原型仍待最终体验验收。本文件记录产品要求，不代表功能已经实现。**

**优先级**：P0＝首个正式版本必须具备且通过验收；P1＝后续重要增强；P2＝长期扩展。八大模块均须在首版形成可用闭环。开发顺序可依赖关系分批进行，不意味着八个模块同时编码。技术实现、外部授权和测试门槛仍需在 W2–W4 细化。

## 0. 用户、范围与共同约束

- **目标用户**：高校学生，以上海交通大学为第一试点；无交大身份的用户也可独立注册并使用非校园功能。
- **首发系统**：Windows 桌面优先，macOS 同期适配和测试；不能把 WSL、Obsidian、某个云模型或学校服务当成基础操作的必需依赖。
- **核心路径**：收集课程/邮件/文件与个人事项 → 整理任务和知识 → AI 提议规划 → 用户确认 → 专注或协作执行 → 更新记录及复盘。
- **数据原则**：本地优先、基础能力离线可用、可选云同步、开放格式导入导出；PDF、录音等大型原始文件按**单个文件**选择是否同步，支持批量操作和逐文件覆盖，新导入的大文件不默认上传。
- **AI 原则**：本地/云端混合，用户自备 API Key 或本地模型；按数据源、文件夹及 AI 项目授权；本地文件访问授权与发送数据给云模型的许可相互独立；高影响外部操作必须单独确认。
- **权限和安全**：最小权限、个人与小组数据隔离；应用限制始终保留紧急退出；邮件永不未经用户逐次确认而发送。

### 统一状态与输入

- **固定日程 Event**：标题、开始/结束时间、时区、地点、重复与课程周次、来源、提醒、锁定状态。
- **任务 Task**：标题、描述、来源、截止时间、预计耗时、优先级、依赖、子任务、负责人与附件、个人进度；团队任务另含可选验收状态。
- **资料 Resource**：原文件、来源路径或链接、课程/项目、索引状态、内容片段、权限、云同步选择。
- **外部绑定**：平台、外部 ID、来源链接、授权范围、最后同步状态、去重/冲突记录。
- **待确认事项**：来源片段、AI 提取结果、可信度/模糊提示、用户接受/修改/忽略状态；未确认前不进入正式日程。

## 1. 日历与任务（P0）

| 编号 | 输入 → 处理 → 输出 | P0 可检验的验收条件 |
| --- | --- | --- |
| CAL-01 日历显示 | 课程、事件、工作时段 → 合并时间轴 → 日/周/月/学期视图 | 正确展示跨天、时区、单双周、周次范围和例外日期 |
| CAL-02 手动管理 | 标题、时间、地点、备注、重复规则 → 创建/编辑/取消 → 事项 | 操作可保存、重启恢复；删除前有明确提示和恢复路径 |
| CAL-03 校园同步 | Canvas/教务授权 → 只读抓取、增量更新、去重 → 课程/作业 | 真实账号可读取数据；校方状态与个人进度分离；同步不覆盖本地备注和子任务 |
| CAL-04 候选收件箱 | 邮件/AI 提取结果 → 识别冲突、编辑候选 → 用户确认 | 未确认的候选不直接加入正式任务/日历；重复提取不重复创建 |
| CAL-05 任务管理 | 截止时间、预计耗时、优先级、子任务、附件 → 维护状态 → 待办 | 支持待办/进行中/完成/延期/取消；团队任务可含待认领、待验收、退回 |
| CAL-06 时间安排 | 空闲时段、任务约束 → AI 拆分并提出时间块 → 规划候选 | 确认后才应用；锁定的课表/会议不被自动覆盖，可拖动调整和撤销 |
| CAL-07 提醒与冲突 | 事项、提醒规则 → 本地调度、冲突检测 → 通知/冲突提示 | 支持多次和提前提醒；过期、禁用通知、无权限时显示实际状态 |
| CAL-08 离线编辑 | 本地变更 → 持久化及同步队列 → 待同步数据 | 断网可编辑；联网后同步冲突不被静默覆盖 |

**主流程**：用户绑定 Canvas 和教务 → 自动出现课程、作业与来源链接 → 添加个人子任务及备注 → AI 提出可用时间段 → 用户确认 → 提醒与执行。外部作业被用户标为完成不等于向 Canvas 提交；实际提交状态仍取自校方。

**失败/边界**：校园授权失效、限流或课程临时调课时保留本地缓存并提示新旧差异；不将无依据的模糊日期猜测为确定事件。

**P1**：经过合法授权的 Canvas 写入、复杂外部日历双向编辑、更多高级日程规则。

## 2. 个人知识库（P0）

| 编号 | 输入 → 处理 → 输出 | P0 可检验的验收条件 |
| --- | --- | --- |
| KB-01 多格式导入 | PDF、Word、PPT、Markdown、TXT、图片/截图、网页、音视频 → 解析/OCR/索引 → 资料 | 能查看原件与抽取内容；解析失败不删除原件，错误可定位 |
| KB-02 录音转写 | 授权录音/视频音轨 → 本地或经许可的 ASR → 带时间定位的转写 | 可编辑并保存转写；可回溯音频时间段；不强制安装 WSL |
| KB-03 本地开放存储 | Markdown、Obsidian Vault、附件文件夹 → 建立/更新索引 → 知识库 | 不安装 Obsidian 仍可完整使用；外部编辑可重新识别，原文件可迁移 |
| KB-04 搜索与 AI 问答 | 查询、授权文档 → 全文/语义检索及生成 → 带引用回答 | 显示文件、页码/段落/时间戳等可获得的出处；无依据不得伪造引用 |
| KB-05 知识图谱 | 文档概念 → AI 提取节点及关系 → 图谱 | 可查看、增删、修改、合并节点/关系；区分 AI 推断和用户修正 |
| KB-06 跨文档关联 | 多篇资料 → 找到相同/相关概念 → 跨资料链接 | 每条自动建议可查看来源及依据，用户可修正；不自动暴露无权资料 |
| KB-07 增量更新 | 新增/修改资料 → 重新索引、差量更新 → 图谱与检索结果 | 不产生无故重复节点，不覆盖用户手动建立的关系 |
| KB-08 自动复习 | 知识点/错误记录 → AI 生成闪卡、选择题、简答题 → 自测题 | 用户可作答、查看反馈、更正题目、记录掌握度 |
| KB-09 间隔复习 | 作答记录、复习历史 → 更新复习时间 → 复习计划/日历候选 | 完成一轮后产生下一次复习安排；用户可调整或跳过 |

**主流程**：导入教材 PDF 和课堂录音 → 转写与校对 → 生成带依据的知识图谱及跨文档连接 → 用户修正 → 生成复习题 → 更新掌握程度与复习计划 → 日历/规划模块使用复习任务。

**失败/边界**：扫描件 OCR 错误应标注低可信内容；云模型无授权不可上传文档；本地外部文件改名/移动要可重新定位或提示失效。大型原件的云同步由用户逐文件决定，图谱索引与实际文件同步状态分开显示。

**P1**：模拟考试、薄弱知识点专项训练、复杂学习评估、Obsidian 深度插件联动。

## 3. 专注与自律（P0）

| 编号 | 输入 → 处理 → 输出 | P0 可检验的验收条件 |
| --- | --- | --- |
| FOC-01 专注会话 | 任务、时间、计时模式 → 开始/暂停/结束 → 记录 | 实际耗时准确归属任务，重启可查看 |
| FOC-02 程序限制 | 黑/白名单、时长、用户许可 → OS 适配层实施限制 → 限制状态 | Windows/macOS 分别真实测试；限制不可用或未生效时如实提示 |
| FOC-03 安全退出 | 退出请求、超时、崩溃、重启或撤权 → 清除限制 → 正常使用 | 始终可紧急退出；不得阻断系统恢复或必要通信 |
| FOC-04 完成判断 | 实际专注、用户完成确认 → 更新个人任务进度 → 结果 | 单纯计时结束不自动视为任务完成 |
| FOC-05 虚拟奖励 | 完成结果、积分规则 → 计算积分/等级/徽章 → 奖励 | 重复上报不重复领取，可追溯积分来源 |
| FOC-06 自定义奖励 | 兑换条件、用户自定现实奖励 → 积分兑换 → 记录 | 可创建、调整、确认兑换；不自动执行购买等现实操作 |
| FOC-07 数据统计 | 会话、任务、退出情况 → 汇总 → 日/周趋势 | 能按任务和时间段查看专注与提前退出记录 |

**主流程**：选择任务 → 配置时间和需要限制的软件 → 查看风险及退出方式 → 明确授权 → 专注 → 用户确认完成情况 → 更新统计与积分。

**安全边界**：不擅自杀死可能包含未保存数据的程序；不阻止任务管理器、系统安全或恢复机制；不能宣传“绝对无法绕过”。任何异常都应优先解除限制。安全保护详见 [SAFETY_AND_PRIVACY.md](SAFETY_AND_PRIVACY.md)。

**P1**：自适应限制、深层习惯分析、桌宠与成就互动。

## 4. 小组协作（P0）

| 编号 | 输入 → 处理 → 输出 | P0 可检验的验收条件 |
| --- | --- | --- |
| COL-01 账号身份 | 独立邮箱注册、可选 jAccount 绑定 → 身份关联 → 用户账号 | 无交大身份仍可使用群组；校园绑定不自动获得管理员权限 |
| COL-02 群组与成员 | 名称、邀请、角色 → 创建/加入/退出 → 小组空间 | 邀请与退出可操作；权限变更立即限制后续访问 |
| COL-03 实时聊天 | 文本、附件 → 消息发送与同步 → 群聊 | 正常在线可互通；离线/失败消息不能伪装已送达 |
| COL-04 团队文件 | 文件、目录、角色权限 → 存取与共享 → 项目资料 | 未授权成员不能读取或修改 |
| COL-05 个人知识共享 | 用户选中的文档/节点、只读或编辑权 → 显式共享 → 团队知识 | 私人资料默认不可见；支持撤销后续访问，说明已下载副本无法收回 |
| COL-06 任务分配认领 | 任务、截止时间、责任人 → 指派或自由认领 → 看板与个人待办 | 支持单人/多人、子任务、评论、附件、进度 |
| COL-07 可选验收 | 完成记录与成果 → 自完成或管理者审核 → 通过/退回 | 开启验收的任务不可由普通成员直接通过 |
| COL-08 团队进度与日历 | 任务、里程碑、成员可用性 → 汇总 → 团队视图 | 个人只显示负责事项；默认不泄露私人日历细节 |

**主流程**：创建群组 → 邀请与授予角色 → 群聊和选择性共享资料 → 发布/认领任务 → 成员上传结果 → 按规则通过或退回 → 个人日历及团队进度同步。

**失败/边界**：退出或撤权后不能继续浏览受保护的新数据；云端离线时本地已有缓存须标注状态，待同步操作不得声称已发布。权限由服务端最终校验，不能仅依赖客户端隐藏按钮。

**P1**：多人实时共同编辑、高级工作量分析、复杂自动分工。

## 5. AI 智能规划与 AI 项目空间（P0）

| 编号 | 输入 → 处理 → 输出 | P0 可检验的验收条件 |
| --- | --- | --- |
| AI-01 日/周规划 | 待办、固定日程、优先级、耗时 → 分析空闲时间 → 计划建议 | 不覆盖锁定日程；用户可修改、采纳、拒绝 |
| AI-02 长期目标 | 目标、截止日期、可用时间 → 阶段拆解 → 里程碑和任务 | 可生成跨周或更长期阶段任务，保留用户修改 |
| AI-03 个性化与动态重排 | 学习偏好、专注记录、临时事件、延期 → 重新评估 → 调整建议 | 遵守休息等明确约束；新建议不静默覆盖原计划；可撤回 |
| AI-04 知识复习联动 | 掌握度、到期复习项 → 安排复习 → 时间候选 | 经确认进入任务/日历，说明安排依据 |
| AI-05 项目空间 | 用户目标、选定文件/文件夹/知识库/邮箱/小组数据 → 建立作用域 → AI Workspace | 不同项目不默认互通私有上下文；可查看当前授权 |
| AI-06 细粒度权限 | 读取/生成/修改、按次/会话/项目有效期 → 权限检查 → 允许或拒绝 | 文件夹越界访问被阻止；默认只读；可撤销，敏感修改可审阅 |
| AI-07 云模型权限 | 本地数据许可、外传许可、所选模型 → 操作前检查 → 受控请求 | 有本地读取权不等于可传到云端；不允许越权读取小组资料 |
| AI-08 模型配置 | 用户自备 Key、本地服务 → 连接测试、选择模型 → AI 能力 | 可切换、停用、查看错误与用量；密钥不进入仓库或普通日志 |

**主流程**：创建“期末复习”AI 项目 → 指定本地课程文件夹、知识库与日历范围 → 设置本地/云端模型权限 → 输入目标 → AI 拆分并提出计划 → 用户确认后应用 → 根据实际进度提出调整。

**失败/边界**：云模型/网络不可用时基础日历、任务和资料浏览不受影响；AI 生成的内容为建议，不能把原始邮件或文档中的指令当成提升权限的命令；共享修改、对外发送等高影响操作仍须独立确认。

**P1**：复杂自主 Agent 工作流、限定范围内更多低风险自动化、项目方提供体验额度。

## 6. 数据接入与扩展（P0）

| 编号 | 输入 → 处理 → 输出 | P0 可检验的验收条件 |
| --- | --- | --- |
| INT-01 SJTU Canvas | 用户 OAuth 授权 → 读取课程、作业、日历 → 规范化数据 | **真实账号**读取成功；正确处理分页、去重、失效授权；默认不回写 |
| INT-02 SJTU 教务 | jAccount 合法授权 → 课表 → 课程日历 | 真实课表验证周次、节次、地点和学期 |
| INT-03 SJTU 邮箱协议 | 合法授权、邮件接口/IMAP/SMTP → 读取和发送适配 → 邮件模块 | 真实收发测试成功；发送与读取能力分离 |
| INT-04 Google Calendar | OAuth → 读取/增量同步 → 本地日历 | 可真实授权；单向同步、错误提示和断开生效 |
| INT-05 Microsoft Outlook | Microsoft 账号委托授权 → 读取日历 → 本地日历 | 支持实际可授权账户；组织管理员拒绝时如实提示 |
| INT-06 Notion | 用户授权指定页面/数据源 → 字段映射和同步 → 笔记/任务 | 真实数据可用；不匹配字段或访问权限不足能提示 |
| INT-07 通用导入导出 | ICS、CSV、Markdown 等 → 预览、映射、去重 → 可迁移资料 | 导入失败可回滚；导出后可重新导入主要字段 |
| INT-08 连接控制台 | 连接器配置 → 显示授权、上次同步、限流/错误 → 管理入口 | 支持手动同步、重新授权、断开、查看状态 |

**真实接入的四层状态**：接口文档存在 ≠ 已开发连接器 ≠ 测试账号通过 ≠ 普通用户可正常授权发布。Canvas、交大邮箱、教务、Google、Microsoft、Notion 的最终 P0 验收均要求至少具备合法授权和真实数据测试；外部审批属于显式项目风险，不能以模拟器冒充正式通过。

**职责**：接入模块处理认证与数据映射；邮箱的分类、草稿及发信体验由第 7 模块负责；课程及任务业务由第 1 模块负责。

**P1**：第三方日历双向编辑、更完整的 Notion 写入、Gmail/Outlook 专用邮件接入、新增高校连接器。**P2**：公开插件市场与更广泛的生态。

## 7. 邮件管理与 AI 通信（P0）

| 编号 | 输入 → 处理 → 输出 | P0 可检验的验收条件 |
| --- | --- | --- |
| MAIL-01 邮箱连接 | 交大邮箱授权 → 真实同步 → 邮件列表 | 收件、重连、撤销授权可操作；凭据安全存储 |
| MAIL-02 独立邮件中心 | 收件箱、线程、附件、搜索 → 展示/操作 → 邮件阅读与草稿 | 收件、已发送、草稿状态可查；本地缓存删除不更改服务器原件 |
| MAIL-03 AI 摘要与分类 | 用户授权范围内邮件 → 自动分析 → 重要性、摘要和分类 | 输出回链原邮件，错误可手工纠正 |
| MAIL-04 日程/任务候选 | 日期、会议、行动项 → 提取和去重 → 待确认建议 | 用户批准后才创建；模糊时间提示，不自行猜测 |
| MAIL-05 拟写回复 | 用户目的、选中线程 → AI 起草/润色/翻译 → 可编辑草稿 | 支持新邮件、回复、回复全部、转发；草稿保留修改 |
| MAIL-06 主动建议 | 需要回复的邮件 → 生成建议草稿 → 待审核 | 不发送任何未经逐次确认的内容 |
| MAIL-07 监督发送 | 最终收件人、Cc/Bcc、主题、正文、附件 → 预览确认 → 单次真实发送 | 实际发送前必须逐次确认；回复全部不可偷偷扩大收件范围 |
| MAIL-08 结果核验 | 发送响应/超时 → 核对状态 → 成功/失败/待确认 | 结果未知时不盲目重发；离线不假装成功 |
| MAIL-09 安全控制 | 邮件正文、附件、云 AI 授权 → 权限与提示注入防护 → 受控处理 | 邮件中的恶意指令不能变更权限、泄露数据或触发自动发送 |

**主流程**：收取邮件 → AI 摘要、提取会议和待办 → 用户审阅确认日历候选 → AI 准备回复草稿 → 用户核对账号、全部收件人及附件 → 明确点击发送 → 核验结果。

**P1**：Gmail/Outlook 专用邮件 OAuth 连接器、更丰富的批量规则；仍不允许未获用户确认的自动发信。详见 [EMAIL_WORKFLOW.md](EMAIL_WORKFLOW.md)。

## 10. 云同步、AI 数据权限与非功能性要求

### 文件级云同步

- 个人任务、日历、用户设置等可选择开启跨设备同步；基础数据离线可用。
- **PDF、录音、视频等大型原始文件逐个选择**：支持批量选择但最终可单文件覆盖；未选择的文件不得上传；新文件不因处于某个文件夹就默认上传。
- 另一设备可见元数据/占位信息，按需下载已获同步许可的原件；不同 OS 的本地文件路径需要重绑定。
- “停止未来同步”与“要求删除云端副本”是不同操作，须分别说明。
- 同步冲突必须检测并保留可恢复版本，不能静默覆盖；本地原件优先保护。

### AI 访问授权

- 用户可按**文件、文件夹及子目录、知识库、邮箱文件夹、日历、小组空间、Git 仓库**为 AI 项目指定数据范围，并可排除子目录。
- 支持仅本次、当前会话、指定期限、项目持续有效等授权期；默认只读，修改和外部操作分别授权。
- 本地读取与云模型传输单独开关。上传给外部模型的数据无法保证事后撤回，因此应明确告知范围。
- AI 只能获得“用户本身权限 ∩ 项目授权 ∩ 当前操作授权”的交集；任何小组资料访问须遵守成员角色。
- 仅依赖提示词禁止越权不满足验收要求，必须有实际权限执行层。
- API Key/令牌存放在 OS 安全凭据区，不能写入公开仓库、普通日志或未经授权的同步资料。

### 平台与可靠性

- Windows 11 和确定支持版本的 macOS 均须通过主要功能回归；具体最低版本、芯片架构及签名方案待 W3 验证。
- 离线时可管理本地日历、任务、资料和已有的复习记录；实时聊天、外部邮件和 API 同步须诚实显示离线状态。
- 原始文件解析失败、网络失效、OAuth 撤销、同步冲突、软件重启均不得造成无提示数据丢失。
- 原生专注限制必须分别在两种 OS 上通过安全退出、超时解除、崩溃和重启恢复测试。
- 可用性与性能量化阈值（启动耗时、搜索响应、同步延迟等）在 W3/W4 根据测试设备和真实接口制定。

## 12. P1/P2 总结与待验证项目

**P1**：复杂 Canvas 写入与第三方双向日历、Gmail/Outlook 专用邮箱、模拟考试和薄弱知识专项、深度 Obsidian 插件、多人实时共同编辑、更高级自主 Agent、桌宠、AI 动态工作台、官方可选 AI 体验额度。

**P2**：插件与主题市场、更多高校服务生态、移动端等。

**W3/W4 必须验证但本轮不擅自定稿的项目**：

1. Canvas、交大教务和邮箱的应用申请及真实用户授权；Google/Microsoft/Notion 的公开 OAuth 发布条件。
2. 本地模型的最低硬件条件、ASR/OCR 依赖、打包体积和双 OS 可用性。
3. 云同步的加密方案（含是否/哪些数据适合端到端加密）、容量上限、留存策略及冲突机制。
4. 角色权限详细矩阵、团队文件配额、审计与数据删除语义。
5. 各功能的量化性能阈值、验收测试数据和操作系统版本矩阵。
6. 用户协议、隐私政策、著作权/课程录音合规及自律限制安全发布审查。

**W1 结论**：八大模块、主要流程、功能级优先级和可检验的 P0 条件已获用户集中审阅确认。W2 交互已形成可供 W3 对照的规范和模拟原型，本次文档提交不代表真实开发与测试完成。

### W2-新增的细节解释（与本 PRD 具有相同的首版 P0 约束）

- `COL-07`：P0 允许无审核直接完成或**一个负责人**验收；按任务重要性配置多个审核人、`n 选 k` 或分阶段票数属 P1，但需要预留 UI/模型扩展位置。此项不改变首版可选审核功能。
- `KB-05/06`：图谱关系的 AI 建议必须与人工确认状态分层，有可点击证据；未核验关系默认不能偷偷进入正式复习。
- `KB-08/09`：系统建议掌握度与用户覆盖后的最终值均应可理解，后续复习依用户最终确认的掌握程度安排。
- `CAL-06/AI-01～04`：AI 任务规划建议以**独立时间块**呈现并可选择性批量应用，锁定原日程与任务截止时间不自动改变。
- `AI-05～07`：像开发工具 Project 一样单项目指定资料与服务范围、排除子目录及有效期，真正校验用户+项目+操作权限；本地读取与云模型外传许可分开。
- `MAIL-03～09`：AI 可按邮箱及文件夹范围主动提取建议，但任何新邮件/回复/回复全部/转发必须完整预览并逐次人工确认发送；API 超时不得自动重复发信。
- `FOC-02/03`：轻量和严格专注共存；严格模式用户确认、权限失败降级、紧急退出/崩溃/重启恢复均属于 P0 发布阻塞项。
- `DASH-02～04`：用户主题/背景、组件显隐/排序/基本尺寸、布局预设和重启持久化均为 P0，AI 自动动态重排布局为 P1。
- `PRD §10`：大原件按**单个文件**保留本机/同步元数据/上传原件；跨 Windows/macOS 路径重新绑定，停止同步与删除远端副本分开，冲突保留可恢复版本。
- `COL-05`：共享**个人知识子集**须明确选择文档/节点/集合、目标角色及撤权，不因文件夹被 AI 项目读取而自动对团队开放。

**实现提示**：W3 的接口、数据表及权限引擎应对照以上细化要求，W4 的验收须同时引用本 PRD 15 条 E2E 和 W2 24 条 UI/UX 场景；对缺少真实第三方授权或双 OS 真机能力的 P0 不得虚报已实现。
