# ALPHA-FOC-005 — 本地专注 7/30 天趋势与连续完成天数

> 2026-11-25；代码能力不等于 Windows/macOS 真机验收。独立于 #48 视觉改版方案，不改变专注积分规则、数据库 Schema、Supabase 或用户凭据。

## 真实需求和边界

旧版专注模块提供单次计时、最近 500 条记录和累积积分；没有近一周/一月的学习趋势，也没有可以自查的连续完成天数。特别是不能直接以最近 500 条列表推导全量统计——高频记录会遗漏当月旧条目。

本轮采用 Electron Main 的只读 SQLite 聚合，把报告限制在**最近 30 个本地日历日**，提供最近七天与之前七天对照、30 天有效分钟/场数/积分、每日分钟和完成数，以及当前连续完成天数与近 30 天窗口内最长连续天数。

## 规则

- 使用电脑 Intl 确认的 IANA 时区（例如 Asia/Shanghai、America/Los_Angeles）分组；**每段记录全部归属结束当天**，不跨日按分钟拆分。这样夜间学习的归属和图形具有确定性，但并不是按每一分钟真实发生时间归属的热力图。
- 只有完成预定时长的记录计入连续完成天数；提前结束的有效秒数计入总分钟和场次，但不会产生完成积分或打断先前已完成的记录。
- 连续天数从今日往前计算；如果今天还没有完成，但昨天完成，则保留截至昨天的连续天数，直到当天结束为止。跳过一个已结束的空白日则归零。最长连续值只在这 30 天窗口内计算，不能误称历史最高。
- 秒数先按所选期间累加，再向下取整为有效分钟；因此每天图上整数分钟之和有时不等于整周分钟，属正常精度差。
- 时间来源为旧版估算的记录仍计入专注秒数，单独展示数量提示；不将它们视为精确观测的真实壁钟起止时间。用户记录的时间不能作为反作弊真实性证明。
- Main 按当前时间向前读取 32 个 UTC 日的记录，应用 IANA 时区过滤为精确 30 本地天；最多扫描 20,000 条，超过上限返回明确错误，**不输出不完整统计**。这与 UI 的最近 500 条历史截断完全独立。
- 仅通过固定只读 focus:insights IPC 接受严格校验的时区标识，不接受自定义 SQL、数据库路径、任意任期范围或未来修改积分的输入。原始标题、私人内容不出本机，不连接云端。
- 不增加 SQLite 版本与依赖。原有 FocusTimer、评分与积分计算逻辑完全不改。

## 实现与手工验收

- src/main/focus-insights.ts：IANA 校验、日期分组、7/30 日总量和连续天数纯计算。
- src/main/local-store.ts：从 SQLite 读取完整受限窗口，拒绝过量记录，不依赖最近 500 条历史。
- src/main/index.ts、src/shared/ipc-channels.ts、src/preload/index.ts、src/renderer/src/vite-env.d.ts：trusted IPC 和 TS 类型完整传递。
- src/renderer/src/FocusInsightsPanel.tsx、App.tsx：现有专注页面内可访问的最近 7 天条形进度、30 天表格、完成连续天数，完成专注后刷新。没有更改 #48 样式设计或全局 CSS。
- src/main/focus-insights.test.ts：固定时区、上海跨 UTC 午夜、洛杉矶夏令时、旧版估算场次、最近两周和超过 500 条 SQLite 历史的回归测试。
- 自动化门槛：npm ci、npm run typecheck、npm test、electron-vite build 和打包离线 Worker smoke，Windows/macOS 两套 CI 在最终 SHA 必须全绿。
- 真机待做：跨日计时结束、夏令时环境、电脑切换系统时区、远早于 30 天的记录、重启再开、图表可读性及窗口缩放。
- **非本轮**：FOC-003 程序/网站限制、FOC-004 安全退出与系统授权、FOC-006/007 奖励兑换；不要将纯专注统计称为这些功能已完成。
