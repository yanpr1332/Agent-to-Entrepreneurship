# ALPHA-FOC-006 — 自定义虚拟奖励与本机积分兑换账本

> 2026-11-25。实现 PRD FOC-05/FOC-06 中的本地可创建/编辑/兑换部分，不包括现实消费、交易或系统级专注约束。双平台 CI、独立 Review 和 GUI 仍分别验收。

## 用户操作与严格边界

1. 「专注与自律」页面看到本机已赚积分、历史已兑积分、可用余额和仅按**累计赚取**计算的虚拟等级/徽章。
2. 创建至多 100 个奖励；填写名称（1–100 字符）、说明（最多 500 字符）和兑换积分（1–1,000,000 整数），支持修改价格、名称、说明、停用/重新启用。停用代替删除，保留旧兑换可追溯。
3. 用户自己选择兑换并明确二次确认；Main 依据已完成专注记录的真实 SQLite 积分和所有历史兑换成本决定是否可兑。余额不足、奖励已停用、伪造积分/任意字段立即拒绝，不允许 Renderer 传余额。
4. 记录不可从产品 UI 编辑的**原奖励名称、原单价、兑换时间、兑换请求 UUID**快照，最近显示 100 条但余额始终计入完整历史。修改价格不会追溯更改旧凭据。兑换后不能通过 UI 取消或退款。
5. 同一个兑换请求 ID 重试返回原凭据，不能额外扣分；在不同奖励使用同一 ID 拒绝。一次数据库 `BEGIN IMMEDIATE` 事务里检查余额并写入，避免两窗口各自以为同一余额仍可消费。
6. 兑换是**用户对自己的计划与承诺**：应用不会购票、发货、运行付款、连接第三方或强制要求用户兑现。属于本地无加密 SQLite 信息，用户可接触数据库，因此不是防篡改/作弊证明，也不是可流通货币或金融资产。

## 数据迁移

- 主本地任务数据库 `study-anchor-tasks.sqlite` v10 → v11：`focus_rewards` 和 `focus_reward_redemptions` 两张表，奖励版本更新时间用于 CAS 乐观并发修改；后者外键保护奖励来源（无删除接口）。
- Electron Main 在打开旧数据库前调用 `backupBeforeMigration(...,11)`，该备份基于 WAL-aware 在线 SQLite backup 和 quick_check，不改变受限文件名白名单。真实用户备份是**未加密**的，应由用户自行保护。
- 专注积分生成不变：只有完整专注奖励分钟积分，重复上报会话不重复奖励。新的兑换成本不直接改写专注记录，累计已赚总额仍由 `focus_sessions` 计算。
- 新增只允许四个固定类型化 IPC：`focus:rewards` / `focus:reward-create` / `focus:reward-edit` / `focus:reward-redeem`。不开放 SQL、文件路径、实际积分变更、云端/网络行为。
