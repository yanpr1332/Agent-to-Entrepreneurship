# APP-004：本机诊断与安全错误边界（内部 Alpha）

## 本轮实现

- 主进程的全部 **88 个 IPC handler** 经过一个统一的异步异常边界。任何原始异常均被转换为预定义的用户提示；原始异常的 `message`、`stack`、HTTP 响应正文和内部路径**不经过 IPC 回传 Renderer**。
- 为 Canvas 授权过期、Canvas 访问受限/限流以及 SMTP 已发出但回执丢失的情况保留**精确的静态提示**，特别是邮件状态不明时应先查看已发送邮件，避免重复发送。
- 新增 `src/main/diagnostics.ts`：只接受静态枚举事件代码、固定的模块/IPC 通道名和 ISO 时间；意外传入的自由文本会被替换为 `app`。**接口不接受请求参数、Token、邮箱地址、文档内容、AI 提示词、文件路径或原始 Error 对象**。
- 事件写入当前 `app.getPath("userData")/ate-diagnostics.jsonl`，大小上限 128 KiB，超过后清空旧事件并开始新记录；写入失败不影响原业务。Unix 新文件权限 0600，不暴露给 Renderer。终端也只收到同一份经约束的事件元数据。
- 覆盖程序启动、沙箱兼容模式提醒、SQLite 初始化失败、AI/邮件降级、Canvas/邮箱同步失败，以及 IPC 调用失败。
- 本地数据目录初始化失败时不再向终端输出失败路径或原始错误；数据库开启失败也不输出数据库路径与异常详情。现有中文安全操作提示保留。
- 保留现有 `contextIsolation`、`sandbox`、可信来源校验和精确 IPC allowlist，没有加入任何日志上传、远程崩溃收集或 Renderer 读取日志的 API。

## 数据安全与操作边界

| 事件字段 | 示例 | 会写入什么 |
| --- | --- | --- |
| time | `2026-11-11T12:00:00.000Z` | 当前时间 |
| level | `warning` / `error` | 固定级别 |
| code | `IPC_FAILED` | 编译期/运行期双重白名单 |
| operation | `canvas:connect` | 固定 IPC 名或预定义模块名 |

**不会写入**：Canvas Token、AI API Key、邮件账号/主题/正文、密码、HTTP URL、SQL 值、文件绝对路径、请求参数、堆栈或任意 `error.message`。

诊断文件并未加密（和设备上的其他本地普通文件一样，可以被能读取当前用户目录的人查看），但内容只有低敏事件元数据。**请勿把整个用户数据目录上传到公开 Issue**；有需要只提供经过核对的相关诊断条目。该文件不属于现有 SQLite 快照备份，也不执行远程上传。

## 验证和验收边界

- Vitest 测试检测伪造的 Token/URL/邮箱/路径/邮件正文是否能经日志或 IPC 泄露；验证日志大小限制、权限、写入故障不影响主流程、静态安全状态提示和异步 IPC 包装行为。
- GitHub Actions 仍执行 Windows/macOS 的 `typecheck`、`test`、`build`。
- **真实 GUI、真实 Token / 邮箱 / AI Key 的故障恢复验收仍未完成。** 本轮记录固定失败操作类别，不能精确追踪每种第三方服务返回的底层错误；未来可添加经过审查的标准化错误代码，但不得把原始异常加回日志。
- 仍需扩展 Renderer 内部异常边界和 UI 级错误分类；本轮统一的是 **Main IPC 的外发错误** 和启动/自动同步事件。
