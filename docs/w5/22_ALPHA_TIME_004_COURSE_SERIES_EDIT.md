# ALPHA-TIME-004：手动重复课程按范围修改（PR #29）

> 当前状态：代码已提交，真实 Windows/macOS GUI 验收尚未进行。以 PR 最新 CI 为准，不得仅凭文档把功能标为已验收。

## 本轮功能与边界

在「日历与任务 → 固定课程与 ICS 日历」找到本机手动创建的重复课程，点击「修改本次日期/时间」，在编辑表单里选择范围：

| 范围 | 操作含义 |
| --- | --- |
| 仅修改本次（默认） | 只改这一条，保持现有单次编辑能力 |
| 从本次起（含本次） | 按**当前日期顺序**选择这次及后面的同组课程，不改更早的成员 |
| 整个系列（包括之前） | 修改同组全部存续课程；已被单次删除的条目不会重新出现 |

允许修改名称、开始时间、结束时间和日期。对于批量修改，所选课程的新旧日期差（按 UTC **自然日**计算，不按夏令时时钟小时计算）会应用于所有选中的成员，保持成员彼此相隔的天数。比如每周三课程选中第二周改到周四，则被选中的各周统一向后移动一天。

编辑前界面显示受影响的条目数量，点击批量保存时弹出明确确认。已经单独移动的课程仍保留在系列内，「从本次起」按**当前排序**界定范围；不会按照从前的创建序列重新计算周次。此行为应在 GUI 测试时明确验证。

**安全边界**：

- 只允许以 \`manual:\` 标识的**本机手动创建的重复系列**进行批量编辑。ICS 导入事项（\`ics:\` 系列）与 Canvas 缓存不会被新批量接口修改，继续使用之前的单次编辑/显示管理权限。
- 全部输入由主进程严格校验：允许的 scope、ID、标题、自然日、时间范围；IP C 白名单只新增 \`calendar:fixed-edit-series\`，并保留可信调用方验证。
- 批量更新在同一个 SQLite 事务里执行。主进程按完整受影响集合检查与**已确认学习时间块**是否重叠，任一条冲突均全部拒绝，不能只更新前几次。
- 课程与其他固定事项的重叠维持现有规则：允许并存、界面警告，不擅自移动另一门课程。任务截止日期、原始 Canvas 信息、已确认计划、专注记录和积分均不更改。
- 跨午夜固定事件及不合法日历日期继续被拒绝。该变更**不涉及数据库迁移**：固定日历 SQLite 仍为 v3。

## 集中 GUI 验收用例

1. 按 [README](../../README.md) 使用独立 \`ATE_USER_DATA_DIR\` 启动，工作台显示 SQLite 已连接。
2. 选中 2026-11-25，创建「高数课」，设置 09:00–10:00，重复 4 周。在月/周/日历分别确认 4 条。
3. 选中第二周，点「修改本次日期/时间」，默认「仅修改本次」，改名称和时间，保存后确认另外三周不变。
4. 再选中第二周，切换为「从本次起」，把当前日期向后移动一天，并改为 10:00–11:00；确认更早一周不变、剩余各周都按相同自然日差移动，界面显示受影响数量。
5. 对某个同组事件选择「整个系列」，修改名称/时间，检查所有**仍存在**的组成员一致更新。
6. 创建与某一次目标课程冲突的已确认学习时间块，再尝试批量移动。预期主进程拒绝整组操作，所有课程保持原值；移开冲突时间后才能提交。
7. 对同组先删除某个单次事件，再编辑整个系列，确认已删除的那次**不会重新生成**。
8. 导入一份无敏感内容的有限重复 ICS 文件；检查可以单次编辑/整组删除，但**没有**新的「从本次起/整个系列」批量修改入口。Canvas 同步事项保持只读/可隐藏，不被本功能编辑。
9. 关闭应用并在同一隔离目录重启，检查课程名称、日期、时间、系列归属均持久化，确认旧的独立课程仍正常。

## 自动化测试范围

- 仅未来组成员编辑及整体日期偏移；
- 整组编辑与成员 ID / 系列 ID 保持不变；
- 已确认学习时间块冲突时原子回滚；
- ICS / 独立事项不可绕过权限边界调用批量修改；
- 非法 scope、日期、时间及多余字段拒绝；
- SQLite 重启后的单次修改与后续批量编辑兼容。
