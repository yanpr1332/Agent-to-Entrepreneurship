# V0.1 五人内部 Alpha：4–7 轮交付与验收总计划

> 2026-11-25，用户确认本路线为接下来的开发目标。**本文件是持续执行基线**，每轮必须从 `main` 与本清单对照，更新状态/证据，维持“同一时刻只有一个功能开发 PR”的规则。#48 属于独立视觉规划 PR，不与正在开发的功能 PR 混改。

## 范围与不可删减验收门槛

本项目的第一个版本不是只在单台电脑展示的 UI 演示，而是按 [W4-01](../w4/01_DEVELOPMENT_PLAN.md) 与 [ROADMAP](../ROADMAP.md) 定义的 **V0.1 五人内部 Alpha**：
- Windows 与 macOS 各有**实际可安装、启动、卸载并再次启动**的桌面内部测试包（无应用商店要求）。
- 五个独立团队账号能经真实 Supabase 测试项目/互联网进入同一工作空间；成员、RLS 权限、任务、消息、增量恢复、成员撤权具备端到端证据。
- 个人任务/日历、知识与复习、专注与奖励、AI、Canvas、邮箱、团队、工作台共八大模块具有可演示的**真实基础闭环**；个人数据重启后不丢失。
- Canvas 使用**获授权的真实账号**至少成功读取课程/作业；个人 Token 仅能用于开发者本人合法本地测试，多人 OAuth 若 Developer Key 尚未批准必须标明 Blocked，绝不能共享个人 Token。
- 上海交通大学邮箱使用合法真实测试账号完成 IMAP 收件与 SMTP **单次显式确认发送**，发送未知状态不自动重试。
- 至少一次合法个人 OpenAI API Key 的真实受限调用，确认费用/授权界面；AI 只能使用用户选择的数据，输出必须是候选并经过用户审核，不能未经允许写库/发信。
- SQLite 迁移、备份/恢复、凭据存储、RLS 正/反向测试、断网重连、跨账号隔离和隐私控制达标；不因进度缩短安全边界。

**CI 全绿仅证明代码可构建、测试通过；不能代替实际安装、RLS、真实外部服务或用户端验收。** 外部审批/真实账号与 API Key 由用户合法提供并自行操作，不写入 PR/Issue、测试截图、GitHub Actions、日志、普通 SQLite 或模型提示词。若条件尚不具备，明确记录 Blocked；不伪造成功或跳过门槛。

| 批次 | 主交付 | 完成门槛 |

| 4 / ALPHA-CLOSE-04 | Supabase 测试环境部署手册/RLS/Realtime 最小正反向验证、五账号联机 E2E、团队任务消息与个人增量同步恢复；补齐缺口 | 真实隔离项目、5 个不同账号、撤权、越权、断网恢复和设备切换有脱敏证据；未经授权不代用户部署云资源 |
| 5 / ALPHA-CLOSE-05 | Canvas 与交大邮箱真实授权接入/失败恢复；补齐按需安全读取邮件正文、草稿保存/回复与必要的发送快照字段；Canvas OAuth 的批准依赖保持显式阻塞 | 真实授权 Canvas 课程/作业读取 + 真实 IMAP 正文显示、草稿重启恢复、SMTP 完整预览/逐次确认与投递核验；如果学校拒绝或未授权，记录 Blocked、审批状态和下一步 |
| 6 / ALPHA-CLOSE-06（按缺陷可与 4/5 并行安排但**同一开发 PR 串行**） | AI Provider 真实账号最小调用、知识库来源引导的可编辑闪卡生成与复习核对、规划/邮件/日历八模块串联、自助回归与安全诊断 | 真实模型返回 + 严格外传提示、模型输出拒绝被动执行、完整 Alpha E2E 演示与明确风险清单 |
| 7 / ALPHA-CLOSE-07（仅必要时） | 真实 Windows/macOS 集中问题修复与发布候选冻结；处理 Blocker/Critical、安全/恢复缺陷 | 八模块 E2E 测试通过，Blocker/Critical 归零，安装包、五人体验与验收结果归档 |

每一批次以 **一组可运行功能 + 单测 + 双平台 CI + 使用/验收文档 + 明确剩余风险** 为完成定义；不会为了凑轮次拆碎 PR。外部授权可以并行准备，但不会在缺凭据时编造 API 结果。若技术缺口超出估计，则追加批次并更新本文件，不隐瞒延期。

## 每轮结束后的检查表

- [ ] 代码提交至唯一开发 PR；目标分支来自最新 `main`，不触碰 #48 正在修改的文档/视觉规划
- [ ] 最新 SHA 的 Windows 和 macOS：TypeScript、Vitest、Electron build、离线 Worker smoke 通过
- [ ] 涉及数据库时：跨版本迁移、备份、坏输入、并发和恢复测试
- [ ] 涉及外部账号时：明确账号数据隔离、凭据来源与逐次同意；模拟测试不能冒充真实账号
- [ ] 实际用户验收尚未执行的项，标记「待验收」而非「已完成」
- [ ] 更新本文件和 [W5 验收矩阵](00_ACCEPTANCE_MATRIX.md)，保留外部审批/测试证据缺失信息
- [ ] 只有独立 Review 后才合并；不自动合并

## 明确不阻塞第一版 Alpha 的高级功能

真正不可绕过的系统级第三方应用限制、自动神经模型权重分发、全部学校教务 API、Google/Outlook/Notion 全部正式 P0、P1 高级协作、完整多文档 RAG 和 app store 上架，都不能因为这轮大开发而冒充完成；但不作为 W4 已定义内部 Alpha 的强制最小闭环。正式 P0 不因此被取消。
