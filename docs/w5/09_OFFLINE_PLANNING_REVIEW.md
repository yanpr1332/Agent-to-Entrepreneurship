# W5-10 离线学习规划：候选 → 编辑 → 部分应用 → 撤销

状态：待 GitHub PR 的 Windows/macOS 自动化验证；未进行真实设备 E2E。

## 交付内容

1. **可离线执行的规则候选引擎**，不对外发送资料、邮件或任务。它基于本机 SQLite 中可见、未完成的普通任务和 Canvas 任务，以截止日期优先、同日期内优先级优先排序。在用户指定的 1–21 天窗口、每日 06:00–23:59 内的 30–480 分钟范围中，尝试为每个任务分配一段可用学习时间。每段预计 15–120 分钟，每个候选任务默认只安排一段。最多考虑前 100 个任务。
2. 「AI 辅助规划」导航切片在首版先**诚实标注为「学习规划（离线规则）」**，不冒称真实 AI 模型或已完成 W4 AI-001/002/003。
3. 候选提案存在独立本机 `ate-plans.sqlite`；预览/修改建议**不会更新**权威 `tasks` 表或 Canvas 来源字段。
4. 用户选择任意子集后，可编辑每一段的日期/开始时间，明确点击确认才应用；每次应用重验任务是否仍存在、可见、未完成，以及任务快照 `updatedAt` 和截止日是否改变。
5. 写入候选时，检查是否与任何已确认时间块、同批待应用块相交，拒绝超出预设时间窗及重复应用。所有被选择的时间块在**一笔 SQLite 事务**里应用；有一项冲突则整批不写入。
6. 已确认时间块显示在日历选中日期下方，也在规划页面集中显示。日历中的时间安排与任务的截止日期**不是同一个字段**。
7. 批次撤销只撤销本次确认的时间块，**不删除或修改个人任务**；应用与撤销历史均持久化至独立规划数据库。
8. 手动「备份本地数据库」除任务、邮件头缓存和知识库，还包含 `ate-plans.sqlite` 的 WAL-aware SQLite 快照；现有备份入口不变。

## 安全与限制

- 规划数据不共享到 Supabase 或 Canvas；用户不得依赖此候选来证明教师/学校的官方课表已被读取。
- 当前不会从学校读取固定课程、考试会议、跨服务事件、个人其他日历等外部**锁定事项**，只能规避本应用已有的规划时间块。**在用户应用前必须自行核查课程和其他现实日程**；冲突检测范围仅限同一规划数据库里的已确认时间块。
- 候选规划不是多周目标自动拆解：目前每任务一段估计时长，没有里程碑、资源依赖或动态重排；不能代表 W4 AI 全量验收。
- 当前使用设备本地日期 + HH:MM 民用时间，不存储明确时区和跨夏令时歧义。因此对跨设备、跨时区或夏令时变更时刻的复杂日程仍需后续设计和验收。
- 如果用户之后删除或隐藏已安排任务，先前确认的时间块暂不自动删除；需要用户手动撤销相应批次（待补关联数据清理与提示）。
- 未使用模型提供者、API Key、AI 工具调用、跨文档上下文或外传授权；真正 AI 规划需要单独设计安全调用与模型验证。
- 本轮不新增 npm 依赖、不使用 RDC、不操作用户电脑、不部署云端资源、不直接合并 main。

## 测试目标

- 任务截止日与优先级排序，隐藏/已完成任务排除；
- 预览不修改任务，选中部分才应用；
- 手动修改日期/时间，超窗拒绝；
- 同批内部冲突、已确认时间块冲突、重复点击与其他候选提案重复安排；
- 任务状态变化、截止日变化导致旧提案被拒；
- 整批撤销不影响个人任务；
- 合法民用日期（含闰年）及 IPC 白名单；
- Windows/macOS Electron TypeScript、Vitest、bundle CI；
- **待本地真实验收**：手动创建任务、生成时间安排、只应用一部分、日历查看、撤销、重启持久化及数据库快照检查。

这轮实现是时间安排基础能力，不等于 AI-001/AI-002/AI-003 全部通过。正式 AI 接入、外部日历锁定冲突、时区/夏令时、实时多设备同步仍在后续范围内。
