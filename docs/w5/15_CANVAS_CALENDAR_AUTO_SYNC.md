# CAL-005：Canvas 日历事项自动同步（本机 Alpha）

## 目标和边界

- 复用现有开发者个人 Canvas Token 与 30 分钟自动同步生命周期。自动获取所有已授权、未暂停的当前课程日历事项，**不需要每条手工点击导入**。
- 使用 Canvas 官方 `GET /api/v1/calendar_events`，固定 `type=event`、指定 `context_codes[]=course_ID`、过去 14 天至未来 180 天。与 `/assignments` 分开读取，避免把作业截止日再次写成一条固定课程。
- 只保留课程编号、事件编号、标题和本机日历的日期/时间范围；不保存 Canvas HTML 正文、位置或 Token。按实例 origin、用户账号 ID、课程 ID、事件 ID 联合去重。只读取不向 Canvas 写回。
- 单门课程失败只影响该课程日历，不丢弃其他课程/作业同步；保留旧缓存并给出安全状态。用户在 Canvas 连接页暂停课程，后续不会采集该课程的新作业或日历数据；已缓存事件保留，由用户决定显示或隐藏。
- 所有 Canvas 日历条目默认可见，但可以逐条隐藏/恢复；**隐藏条目保留 6 个日历月**，不会被随后同步重新显示。超过保留期后清理隐藏缓存；如果远端仍有该事件且它继续落在同步窗口内，后续同步可能重新创建。历史 v1/v2 的手动/ICS 事件不受影响。
- 当完整课程窗口内的远端事件消失，将本地条目标为「来源已缺失」，保留供人工核对，但不再占用学习规划时间；不把查询窗口之外的历史事件误判为消失。对无法准确映射为单一本机自然日的跨夜/DST 事件拒绝占用并计入 skipped（不做静默错排）。
- Canvas 日历与个人固定课程共同参与 **规则规划、AI 规划和最终人工应用** 的冲突判断。同步发现与已确认学习时间冲突时仅警示，**不自动移动或删除学习计划**。
- 安全：主进程独占联网、SQLite 和身份校验；Renderer 只能调用固定 allowlist 的事件列表与单条可见性接口；无法提交或伪造课程事件数据。
- 断开 Canvas 后，本机缓存保留，但不能显示/操作其他账号的缓存。安全起见，重新打开应用后须成功验证账号身份才能恢复该账号日历的显示与规划占用。这也是离线 Alpha 的限制。

## 存储和兼容

- `ate-fixed-calendar.sqlite` v2 -> v3：新增独立 `canvas_calendar_events` 缓存表，不混入 `fixed_events`（手动/ICS 由用户自主编辑）。
- 数据库迁移前通过现有 WAL-aware `backupBeforeMigration(...,3)` 备份，并维持旧固定课程、ICS 日历及其编辑/整组删除。
- 原生 ICS 导出继续只包括手动/ICS 事件，**不会默认把 Canvas 课程内容导出**。全体 SQLite 本机备份则包括 Canvas 日历缓存；备份仍未加密。
- 日历列表可包含可见、隐藏及来源缺失的 Canvas 记录，仅当前身份对应的账号可见；日历圆点与规划占用只计算仍可见且来源有效的数据。

## 验收与后续

自动化覆盖：固定授权 API 参数及安全分页、同账号幂等、多账号隔离、隐藏六个月/恢复、来源缺失、不支持跨夜条目、数据库 v2->v3 升级前备份、取消同步后不写入、成功同步后规划避让。

本轮仍需 Windows/macOS CI（typecheck、Vitest、Electron bundle），真实 Canvas Token 和真实课程 API 的本机集成验收不在 CI 中。当前不接 Google Calendar OAuth/CalDAV，也不支持 Canvas 日历向外的双向编辑、区块级课程和跨午夜事件拆分；后续需先完成账号授权及外部连接器模型审查。
