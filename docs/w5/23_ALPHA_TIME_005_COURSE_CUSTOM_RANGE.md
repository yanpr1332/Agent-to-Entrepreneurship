# ALPHA-TIME-005：指定第 N 次到第 M 次的课程修改

> 针对用户新要求：手动重复课程除了“仅本次 / 从本次起 / 整个系列”，还应允许明确选择**闭区间**内的课程，其他成员完全不动。本项尚需人工 GUI 验收。

## 功能规则

- 在本机创建的重复课程中，选中任一成员进入编辑，修改范围选择**指定区间（从第 N 次到第 M 次）**。
- 下拉列出**现存系列**按日期和时间排序的“第 1 次、第 2 次……”；已删除的成员不计入序号。两个端点包含在范围内，右端不得早于左端。
- 可以从该系列的任意成员进入编辑，并另行选择要修改的起点/终点；所点的成员不要求属于最终区间。
- 区间的**第一条课程**为日期偏移基准：在表单“修改后的日期”填写该条的新日期；区间内其他成员按相同自然日差平移，保持相互时间间隔。
- 区间内统一修改名称、开始时刻和时长。区间外成员的 ID、课程标题、日期、时间及系列归属**完全不变**。
- 明确确认所修改的范围和数量。主进程验证区间 ID 均属于本机手动系列、端点按当前日期顺序有序，并在一个 SQLite 事务中检查**所有选中成员**与既有学习计划的冲突；有一条冲突就全部回滚。
- ICS、Canvas 课程不受新接口影响，不修改任务、个人计划或积分；**没有新增数据库迁移**。

## 集中验收案例

1. 按 [README](../../README.md) 使用隔离 `ATE_USER_DATA_DIR` 启动最新版测试分支。
2. 创建连续 6 周的同一课程；进入**第 1 次**课程的编辑窗口，选择“指定区间”。
3. 将“从第几次”设成**第 3 次**，“到第几次”设成**第 5 次（含）**；调整日期为原第 3 次的次日，修改名称和起止时间。
4. 保存后逐一核对：只有第 3、4、5 次发生变化，第 1、2、6 次与编辑前完全相同，课程总数仍为 6。
5. 选第 4 到第 4 次，只修改单个闭区间；验证允许但不会影响其他课程。
6. 将范围调整为第 5 至第 6 次；检查“第 M 次”不能选到早于 N 的成员。
7. 事先在目标区间中间一周建立已确认学习时间块，尝试批量修改，应**整组拒绝且六条保持原样**。
8. 检查 ICS 导入的重复课程及 Canvas 缓存无此区间编辑入口。
9. 重启应用，检查修改结果持久化；再从任一成员进入编辑，看序号与当前排序一致。
10. 回归原有“仅本次 / 从本次起 / 整个系列”及课程单次删除。

相关自动化测试包括闭区间选择、范围外逐行不变、反向/跨系列区间拒绝及冲突回滚。此测试不构成真实 GUI 验收证明。
