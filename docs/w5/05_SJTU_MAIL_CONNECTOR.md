# W5-6 上海交通大学邮箱 IMAP/SMTP 连接器（开发验证版）

状态：代码待 PR 验证；**真实校园邮箱收件/发件需要用户在个人设备上验收**。

## 学校官方服务器参数

上海交通大学网络信息中心的官方服务说明（截至开发时公开的资料）：

| 方向 | 协议 | 服务器 | TLS 端口 |
|---|---|---|---|
| 收件 | IMAP4 over TLS | `mail.sjtu.edu.cn` | `993` |
| 发件 | SMTP over TLS | `mail.sjtu.edu.cn` | `465` |

参考：https://net.sjtu.edu.cn/info/1191/2699.htm
参考：https://net.sjtu.edu.cn/wlfw/dzyj.htm

适用于校级 `@sjtu.edu.cn` 校园邮箱；**医学院独立云邮箱和校友邮箱端点不同，不属于本 PR**。用户本人使用 jAccount 邮箱账号和学校允许的密码/客户端授权码；不得将凭据发送给 AI、团队成员、GitHub Issue、PR 或 CI。

## 已实现的功能

1. 用户在邮件管理页面填写校级邮箱、jAccount 用户名、密码/合法授权码；连接时先对真实 IMAP 进行认证与收件头读取。
2. 确认连接成功且系统安全加密可用后，使用 Electron `safeStorage` 的系统加密能力写入本地密文文件 `campus-mail.enc`，不将密码写入 SQLite、Renderer localStorage 或团队云端。
3. IMAP 使用证书及域名校验的 TLS 993；只读 `EXAMINE "INBOX"`，通过 `UID SEARCH` 与 `UID FETCH BODY.PEEK[HEADER.FIELDS ...]` 读取最近最多 50 封邮件的发件人、主题、日期、Message-ID。
4. 本地 `ate-mail.sqlite` 保存最多 200 条邮件**头部元数据**，以账号、`UIDVALIDITY`、UID 去重。邮箱 UIDVALIDITY 改变时清除失效的旧记录；断开邮箱连接时删除本地密文和邮件头缓存。
5. 应用启动（存在既有连接时）和连接成功时同步；运行中每 10 分钟自动同步；支持手动「立即同步」。网络失败保留已有缓存，不自动改动远端邮件。
6. 用户撰写**纯文本**邮件草稿；点击「预览并请求发送确认」后显示完整的发件人、收件人、主题、正文；必须用户再次点击「确认发送这封邮件」且在 2 分钟内提交一次性确认 ID，主进程才可调用 SMTP 465。
7. SMTP 发送使用证书及域名校验的 TLS，`AUTH PLAIN`（仅在 TLS 内），通过 `MAIL FROM`、逐个 `RCPT TO`、`DATA` 发送 MIME UTF-8 Base64 编码纯文本邮件，不支持附件、CC/BCC、HTML 或自动群发。
8. 用户未确认不发送；确认只允许使用一次。服务器在 DATA 后未明确回复时提示「投递状态不确定，请核查学校邮箱已发送」，**不做自动重试**。

## 安全、隐私、权限

- 邮箱密码仅由 Electron Main 使用，并写入系统加密密文文件；Renderer 不持久化密码，也不向其他连接器或外部云传输。
- 同步和发送权限严格分离：周期调度器只能执行 IMAP 只读同步，不会经过发送确认接口。
- SMTP 收件人限制 1–5 个、主题 180 字以内、正文 10000 字符以内；拒绝 CR/LF 邮件头注入和非法地址。
- 邮件正文与附件**不下载、不存储、不向 AI 上传**；首版不支持完整邮件阅读、搜索文件夹或离线附件。
- 只接受公开的交大邮件服务器常量，不支持任意用户控制 SMTP/IMAP host 或端口，避免 SSRF 和凭据向未知服务器泄漏。
- 收件元数据存储在本地 SQLite，**该元数据文件当前没有额外磁盘加密**。密码文件通过系统加密，但不能把密码保护等同于整盘数据加密；后续加固需引入 OS 存储加密或用户磁盘保护策略。
- 用户断开连接会清空本机缓存，**不会删除交大服务器上的邮件**。
- 不提供自动外发、自动回复、代用户发送、自动批量导入成任务的权限。

## 自动同步与任务候选

符合统一的「授权范围内自动增量同步，不要求手动逐条导入」原则。邮箱与 Canvas 不同：邮件应自动同步邮件头信息，并据此识别可能包含任务的候选，但**不能把每封邮件都变成任务**。当前界面仅根据主题关键词标记可能包含任务的邮件，未实现 AI 语义识别或创建待办。

后续可在明确授权后读取必要邮件正文片段，生成带证据的候选，并由用户确认、隐藏或忽略；邮件正文不得在未经用户明确同意时被发送给第三方 AI。

## 自动化测试 / 真实验收

CI 使用模拟 IMAP/SMTP 协议逐行会话、独立 SQLite 文件及测试专用加密适配器。覆盖：
- 真实协议命令结构和 UIDVALIDITY；
- 收件仅读头，拒绝不完整身份/协议响应；
- 邮件 MIME 编码、收件人限制及头注入保护；
- 不经确认不会发件；确认 ID 一次使用后销毁；
- 发件认证失败时不得发送 DATA；DATA 后未知响应提示不确定状态；
- 加密不可用不得落盘密码；
- 数据库本地持久化、账号隔离和 UIDVALIDITY 变化清理；
- 断开连接清理缓存和待确认发送意图。

**待用户本地人工验收，不应宣称已通过**：

1. 在 Windows/macOS 分别使用自己合法的 `@sjtu.edu.cn` 邮箱在桌面 UI 中连接，验证真实收件列表包含最近邮件。
2. 关闭并重启程序，检查本地邮件头缓存与自动同步。
3. 向自己控制的第二个邮箱地址撰写一封无敏感内容的测试邮件；先检查预览，确认后验证邮件真正送达。测试过程不需要将密码交给助手。
4. 如学校要求 MFA 或客户端专用授权码，请按学校策略操作，不绕过二次认证；若 IMAP LOGIN 或 SMTP AUTH PLAIN 未开放，应调整为学校允许的认证方式后再验收。
5. 断开连接，确认本机缓存与密文凭据删除，学校服务器邮件仍存在。

## 限制与后续

- 首版 IMAP 解析覆盖常见 RFC 2047 邮件头和标准 `UID FETCH` 响应，但需真实校邮箱验证不同服务器扩展；不支持完整 MIME Multipart、正文/附件和全部 IMAP 扩展。
- SMTP 仅验证单封纯文本发送，不是完整通用邮件客户端。
- IMAP `UID SEARCH ALL` 拉取 UID 清单然后选择最近 50 个，邮件量巨大时需补充更高效的增量游标与窗口查询。
- 邮件通知、候选任务、AI 协助写草稿、跨设备同步、完整云端 RLS 不包含在本 PR。
- 没有新增 npm 依赖，不使用 RDC，不在个人设备安装软件。GitHub CI 临时 runner 通过现有锁文件检查。

## 关联原始需求

W4 邮箱真实接入、自动同步、用户确认发送与本地优先安全边界；此 PR 仅为 Alpha 首个最小闭环，不代表八大模块已全部完成。
