# ALPHA-TIME-003：手动安排及修改任务执行时间（PR #28）

> 本轮专注于**任务计划执行时间块**，与任务自身的截止日期区分。代码与 CI 证据不能替代用户集中 GUI 验收。本轮不实现任务具体截止时刻、课程整组编辑或拖拽式日历。

## 已实现的能力

- 「日历与任务」选中一个日期，在 **任务执行时间** 中点击「+ 安排任务时间」，选择可见且未完成的任务、日期、开始时间和分钟数。
- 支持为同一个任务建立多个相互独立的学习时间块；不会覆盖 Canvas 的原始作业数据或任务的 dueDate。
- 已确认时间块可单独「修改时间」或「删除本段」。删除一段不会删除原任务，也不会清空同批生成的其他已确认安排。
- 任意修改和手动创建都在**主进程**检查输入、可见/完成状态（创建时）、日期合法性、同日范围、已确认学习时间和固定课程占用，出现冲突时拒绝写库。
- 学习规划界面继续提供候选建议和「撤销整批」，但现在会提示通过日历修改单段时间；手动安排不混入待审核建议清单。

### 时间字段的独立性

| 类型 | 说明 |
| --- | --- |
| 任务 dueDate | 截止**日期**（不代表日历占用；Canvas 可同步，用户覆盖依旧保留） |
| 任务计划执行块 | 用户手动或规划器确认的时间，15–480 分钟、5 分钟粒度，同一任务可有多段 |
| 固定课程 | 独立的固定日程，手动时间块不会自动挪动课程 |
| 实际专注时段 | 已完成/提前结束的真实执行记录（PR #27），不会自动覆盖已确认计划 |

删除和调整计划时间块不意味着任务完成，也不自动增加专注积分。

## SQLite v1→v2 数据库迁移与备份

本 PR 将 **ate-plans.sqlite** 的 user_version 升至 **2**，在 plan_proposals 表新增 source 字段，用于区分 generated（规划器生成）和 manual（用户手动安排）。历史记录默认是 generated。

启动应用时，在打开数据库执行迁移之前会调用：

\`backupBeforeMigration(userData, "ate-plans.sqlite", 2)\`

此函数使用 SQLite Online Backup API，在独立目录创建经过 quick_check 的未加密快照：

\`ATE_USER_DATA_DIR/backups/pre-migration-ate-plans.sqlite-v1-...\`

**不要在真实唯一数据副本上反复试验升级或降级。** 一旦升级到 v2，旧程序会拒绝直接打开该规划库；完整的恢复 UI 尚未提供，需关闭应用并按受审查的离线恢复流程使用先前的快照。快照内可能包含私人任务标题，不应发送给不受信任的人或外部服务。

## 人工验收案例

1. **数据隔离**：确认启动前已设置独立 \`ATE_USER_DATA_DIR\`，应用显示 SQLite 已连接。
2. **任务来源**：创建任务「Alpha 手动学习」，截止日期为后天；日历选今天，手动安排 18:00–18:45，确认日历出现该计划且任务截止日期没有变化。
3. **多段任务**：为同一任务再安排 19:00–19:30，确认两段同时存在，不会被自动合并。
4. **编辑单段**：将第一段改到另一天的 20:00–21:00；原日期的另一段还在，新日期显示移动后的时间，任务截止日期保持不变。
5. **重叠校验**：尝试把第二段改到当前同日已有固定课程或其他学习计划的时间内，应该拒绝并保留原来的时间。
6. **删除单段**：删除其中一段，另一段依然在，任务仍存在。随后前往「学习规划」，原有候选建议和整批撤销仍能正常工作。
7. **无效输入**：时长 0、14、481 或跨过午夜要被拒绝；隐藏或完成的任务不能作为新的手动安排目标。
8. **持久化**：重启程序，检查手动计划和修改后的时间没有丢失；数据仍在个人本地日历中。
9. **迁移备份**：在专门构造的 v1 测试库上检查 v2 迁移前备份以及旧已确认计划保留；不能通过覆盖真实数据库的方式试验。
10. **关联回归**：专注会话在日历里的实际学习记录仍独立存在；课程时间冲突判断仍正确；Canvas 的自动同步不应擦除个人计划。

## 本轮仍未实现

- 拖拽日历或批量移动整周学习时间；
- 修改任务截止的具体时刻（当前仍是日期级，已支持修改截止日期）；
- 固定课程重复系列的“从本次起/整个系列”批量修改；
- 实际专注与计划块自动一一关联；
- 知识库安全渲染、模糊/语义搜索、小组排行榜、libpng 色彩资源定位。

另需注意：规划器当前可能跳过已经安排了时间块的任务，**手动安排允许用户为同一任务创建多段**；这是两种不同的交互语义。历史手动计划保存的是任务标题快照，未来还需要统一处理任务改名/隐藏后的日历同步策略。
