# W5-8 邮件自动待办候选、人工确认与本地去重

状态：GitHub PR 开发与 CI 验证阶段；真实校邮箱验收留给开发者本人。

## 产品交互

- 邮件仍按原有 IMAP 机制在授权范围内每十分钟自动同步最近邮件的头部元数据；不再要求用户逐封「导入」才开始整理。
- **同步后自动识别**邮件主题中与作业、实验、考试、提交/截止、报名、会议等相关的任务候选。仅使用明确、可解释的本地关键词规则；本轮没有 AI 调用、正文抓取、附件处理或个人数据上云。
- 候选不会自动变为个人待办，避免把一切邮件/通知错误地塞进日历；用户可以：
  - 「创建个人任务」：将当前邮件主题作为任务标题，新建普通本地任务；默认不设截止日期。
  - 「忽略此候选」：记录忽略，下次 IMAP 同步不会重复提示。
  - 「显示已忽略的候选」并「撤销忽略」：可重新审阅。
- 已接受的候选标记为已创建，重复点击或后续收件同步不会重复创建个人任务。
- 邮件 **Date** 是发送时间而非任务截止时间，不能自动写为任务 due_date；用户可在本机日历手动设定真正截止日期。

## 数据与安全

1. 所有已授权邮箱记录通过原有 `CampusMailService.list()`（本机缓存）取得。Renderer 发送的审批请求只包含 IMAP `UIDVALIDITY`、`UID` 与决策，不接受前端传入标题、邮件正文、账户或日期。
2. Electron Main 重新在当前邮箱已授权的缓存中核对源身份，并检查邮件主题符合候选规则，才调用本地写入。
3. SQLite `ate-local.sqlite` 的版本由 v3 升到 **v4**，事务性新增 `mail_candidate_reviews`。每条记录按邮箱 + UIDVALIDITY + UID 唯一键区分；记录「忽略」或「接受」状态、任务 ID 和操作时间。**不储存密码、邮件正文或完整邮件主题**。
4. 接受候选时，本地任务和决策记录在**同一个 SQLite 事务**内写入；中途错误回滚，避免任务已经创建但状态未标记、下一次同步又创建副本。
5. 如果用户之后删除已接受的普通个人任务，候选的已接受记录继续存在，后续自动扫描不会再次创建它。
6. 主动断开邮箱时，在清除密文密码与邮件头缓存后，额外清除该邮箱的候选决策索引；用户先前自己确认创建的个人待办**仍予保留**。如果之后重新连接，同一封邮件可以重新成为候选，这是明确断开并清理后的重置语义。
7. 不变更 Canvas 自动导入、课程屏蔽和六个月隐藏任务保留策略；邮箱候选不是 Canvas 任务，所以不自动沿用其显示/隐藏时钟。
8. 邮件候选与云端 Supabase 工作空间完全隔离；用户的收件箱和邮件主题不会被自动写入共享小组。
9. SMTP 「预览 → 两分钟内一次性确认发送」完全独立，不会因分类、候选审核或周期同步被触发。

## 已知限制

- 关键词分类只能给出「可能是待办」的提示，可能漏报或误报；没有阅读邮件正文的权限，不判断截止日期、附件内容或邮件里的行动主体。
- 第一版只展示最新本地邮件头（沿用 100 条列表、最多 200 条数据库缓存）；不保证遍历历史所有邮件，不是智能全文邮件检索。
- 接受候选后生成**普通本地任务**（无独立的邮件来源展示字段）；邮箱 UUID/UID 关系留在本地候选决策表，未来可为任务增加来源跳转与恢复功能。
- 已接受的任务删除后，仍保持已接受标记直到主动断开邮箱清除记录；不能从 UI 立即撤销这个已接受标记。
- 数据库从 v3 迁移到 v4 时事务回滚，但应用级生产备份/一键恢复仍待实现。真实设备升级前应先人工备份用户数据。
- 本轮不修改用户电脑环境、不使用 RDC、不新增依赖、不部署云资源。

## CI / 本机验收边界

Vitest：
- 主题分类与严格决策输入；
- 同一邮件重复接受只建一个任务；
- 邮件 Date 不被当作截止时间；
- 忽略/撤销忽略在 SQLite 保留；
- UIDVALIDITY 不同及不同账号严格隔离；
- 删除已接受任务后不会重复导入；
- 断开清理决策但保留个人待办；
- v3 → v4 数据库迁移保留旧任务，重启后决策仍在；
- IPC 严格允许列表及新增加的候选操作。

真实验收：开发者在自己设备、合法学校邮箱中连接或使用已有连接，确认真实邮件主题显示候选；手动创建一条任务并重启应用，确认不会再次创建；忽略候选、手动同步、确认忽略仍有效；断开连接确认缓存清除。**不要提供邮箱密码、学校 Token 或真实邮件内容给助手。**

## 后续方向

考虑单独授权的正文摘要、AI 候选提取、截止时间建议和语义去重，但必须有误识别审阅机制、精确授权与退出恢复；不自动批量创建待办，也绝不自动发信。
