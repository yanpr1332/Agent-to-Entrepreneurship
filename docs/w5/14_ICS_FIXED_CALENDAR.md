# W6 CAL-003 / CAL-004: 本机固定课程与安全 ICS 导入/导出

## 范围与操作路径
- 在「日历与任务」选择一天，创建一次性固定课程/活动，或者按星期重复 2/4/8/12/16 周。每个发生日期保存为独立的本地事件。新增周系列支持删除单次或删除整组，也可单次修改标题、日期与时间；升级前历史独立事件仍需单条删除。
- 本地选择 .ics（512 KiB 上限），Main 在用户选择路径后解析至内存，展示**完整标题/日期/时间预览**；用户明确确认后再一次性导入。确认 2 分钟有效，只能使用一次。不会在打开日历时自动扫描或同步其他应用。
- 支持单日 VEVENT：UTC、设备本地浮动时间、IANA TZID 转换、单日全天 DATE，以及有限周 RRULE（FREQ=WEEKLY、COUNT 1–250、INTERVAL 1–8、BYDAY；两年内展开）。支持折叠行与 ICS 转义。夏令时跳时/歧义时刻及跨越时钟切换的事件一律拒绝，双周规则按周一为自然周起点计算。**不支持 UNTIL、RDATE、EXDATE、RECURRENCE-ID、复杂非周重复、跨多日持续事件、VALARM**：任何不支持的事件会使整个文件拒绝。
- 固定事件与个人任务完全分离。手动输入和成功导入的所有事件都视为学习规划的“不可占用”时间。规则规划跳过占用时段；AI 生成候选遇到占用时段则整体拒绝；最终人工应用前再校验一次。反向添加固定事件与现有**已确认**学习计划冲突时也拒绝，避免静默覆盖已有决定。
- ICS 导出仅包含本地固定课程和已导入活动（不包含任务、邮件、Canvas Token、知识库或已确认学习时间块），用户在原生保存对话框中选择文件路径，使用 `wx` 禁止覆盖已有文件。导出的时间为设备本地浮动时间，无绑定时区；跨地区移动请在目标日历检查显示。未调用网络，也不会发送给 AI。
- 重复导入以原 ICS UID 去重，不修改已有条目，且导入批次是单个 SQLite 事务；手工课程由本机生成 ID。源文件未原位修改。

## 存储与备份
- 本机 SQLite `ate-fixed-calendar.sqlite`（schema v2，升级前对 v1 做已验证快照）；限 2000 条事件，支持本机数据库在线备份，与其他 SQLite 一同保存，当前备份仍**未单独加密**。
- 提供唯一九个固定日历 IPC：list/create/delete/edit/delete-series/preview-ics/confirm-ics/cancel-ics/export-ics，均验证 trusted renderer；文件路径只能经 Main 的原生对话框产生。不会将任意路径、文件系统读写接口、SQL 或解析器暴露给 Renderer。

## 自动化测试与验收
- 严格 ICS 白名单：有效日期与本地时间、换行折叠、转义、全天、跨日午夜结束、导出再导入、重复 UID、IANA TZID 与夏令时、有限周重复展开、无法支持的时区/规则/多日活动拒绝。
- SQLite：v1→v2 迁移备份、周系列整组删除、单次修改、ICS UID 幂等、单条删除、已确认学习时间碰撞的事务拒绝、生成规则/AI 建议/最终应用全路径冲突保护。
- Windows/macOS GitHub Actions 运行 typecheck、Vitest、构建。**真实本机 ICS 导入/导出文件选择、时间区、桌面 GUI 验收仍需用户后续执行**。

## 不在本轮的能力
- 不支持全量 ICS 生态（非有限周 COUNT 的 RRULE、UNTIL、时区自定义定义、跨夜/跨多日事件、邀请更新、远端 CalDAV/订阅）；没有原日历文件原子同步、拖拽批量修改课程或跨账户课程锁定。
- 不自动把 Canvas Calendar 事件当作固定课程（当前 Canvas 只同步作业），不自动导入邮件日程，也没有向学校课表进行外部查询。
- 固定课程冲突检测只针对本机时间块，不代表真实学校课表和其他日历已被完整同步。
