# ALPHA-KB-004：本地混合检索 + 单段原文 AI 辅助解释

> 本 PR 只在知识库模块内完成。**不是自动全库 AI 语义搜索，也不是自动检索增强生成（RAG）。** 原始文档和个人数据依然默认只在本机。用户在最终 GUI 集中验收之前不必连接真实 Key；CI 使用模拟和离线测试。

## 两项实现

### 1. 检索结果改为精确优先 + 容错补充

原有实现找到任何精确结果即停止，因此即使另一个文档仅有一个拼写错误也不会出现。现在对每次本地检索：

- 先使用现有 SQLite FTS5/trigram 检索**精确命中**（前 40 条）。
- 如果还有剩余名额，针对归一化后 4–60 字的词句构造参数化 trigram 候选（最多 200 条），按有限编辑距离选择并附加**容错匹配**，保持精确在前，最多共 40 条。
- 用文档 ID + 分块序号去重；返回原文件标题、文档版本、分块号及 PDF 物理页码。
- 所有筛选均在本机，检索不调用 AI，不上传全文，不运行用户输入的 SQL/正则。
- 不承诺 AI 语义理解、同义词识别、跨语言理解或全文智能排序；偶发模糊误匹配仍可能发生。

### 2. 针对当前原文的可选 AI 辅助解释

**仅当用户明确点击三步中的最后一步，才会对外发送**：

1. 先在知识库中选择文档或搜索结果定位到某一原文片段；该片段带有文档标题、版本、原文分块序号和（PDF 时）物理页码。
2. 在当前片段下方输入不超过 280 字的问题，点击「第一步：预览将发送的资料」。软件将问题与**当前这一段文本的前 1150 字符**合成为一次性请求。预览前不会发送资料，且没有应用后台自动检索/自动上传机制。
3. 阅读预览区域中**完整的实际请求**，核对是否愿意把选中的内容送至 OpenAI API。只有点击「确认发送这段原文」后，才复用当前项目的安全 AI Provider：受限 HTTPS 端点、用户自己的加密 Key、daily request cap、请求不自动重试、最多 512 output tokens、\`store:false\` 和 \`tools:[]\`。

发送内容不包含文件源路径、其他片段、附件、完整知识库、Canvas、邮件、日历或同设备其他资料。所选原文被标记为**不可信引用数据**而非系统指令；这有助于减轻但不能彻底消除间接提示注入风险。

回答只在当前知识库 UI 展示，不自动创建复习卡、修改任务、存数据库或覆盖资料。结果显示模型和本机来源的标题、版本、片段序号与页码，并附上**实际发出的原文**供人工核对。该“引用来源”只证明用户选了什么，不代表模型回答已经被准确证实。

**无 Key 仍可完整离线搜索、浏览和复习；不需要联网也不会因未连接 AI 而阻塞知识库。** 要启用单次解释，请在左侧「AI 助手」自行连接自己的 OpenAI API Key，随后返回知识库刷新连接状态。不要上传敏感学校资料或未经授权的第三方文件。用户确认后的外发数据仍受 API 服务商处理政策约束，\`store:false\` 不等同于服务商完全无法访问数据。

## 本地验收

PowerShell，首次下载此独立分支（若 PR 尚未合并）：

~~~powershell
git fetch origin
git switch -c alpha-kb-pr32 --track origin/feat/alpha-kb-004-explicit-ai-cited-explanations
npm ci
$env:ATE_USER_DATA_DIR = "$env:LOCALAPPDATA\ATE-alpha-kb-004"
npm run dev
~~~

已有测试分支时改为 \`git switch alpha-kb-pr32\` 和 \`git pull --ff-only\`。避免重置用户改动。命令说明、Node 24、Electron 缺失安装与安全沙箱见 [根 README](../../README.md)。

### 不联网的检查

1. 导入两个**测试**文件 A 与 B：A 写 \`DNA polymerase reads a template\`，B 写 \`DNA polymeraze copies a template\`。搜索 \`polymerase\`，预期 A 是“精确匹配”、B 是“容错匹配”，不会有重复引用。
2. 点击 A 的检索结果，检查文档标题、版本及片段序号。将 B 改为正确拼写后重新导入，复查两个文档均能够被检索。
3. 保持 AI 未连接，知识库仍可打开文档、阅读 HTML/Markdown/TeX、搜索并建立手工复习卡。AI 区域应提示连接，而不是发起付费请求。
4. 导入含有非敏感文本的长文件，检查选中片段大于 1150 字符时被截断；预览没有自动附带文件路径或其他段落。
5. 切换到另一篇文档/不同片段后，旧的 AI 预览/回答不会被错挂到新来源。重启应用，文档、索引和卡片持续保存，但 AI 单轮回答不被静默写入知识库。

### 自愿进行的真实 API 验收

仅使用无隐私的测试文本，使用自己的 OpenAI Key 并自愿承担可能的 API 费用：

1. 在「AI 助手」配置测试 Key，返回知识库点「刷新连接状态」。输入一句问题，点击**预览**；在没有确认发送时观察 API 使用量不应变化。
2. 检查预览的全部文字、模型和来源信息。点击「取消，不发送」，不应扣减本机请求额度。
3. 再次准备，点击「确认发送这段原文」；可能计费，回答展示在知识库中，能看到来源原文与版本信息。不能把 AI 生成内容当成已验证证据。
4. 模拟 API 失败、取消或配额耗尽：客户端应提示错误/不确定费用，不自动重试、不调用未授权的远程工具。
5. 重启后验证旧 Key 按已有系统加密方案持久化，AI 单轮内容没有自动出现在复习卡、任务或日历里。

## 不属于本轮完成的内容

- 真正的本地 embedding 模型、多语言向量检索（已作为后续 **ALPHA-KB-005** 登记，参见 [26 技术可行性评估](26_ALPHA_KB_005_LOCAL_SEMANTIC_SEARCH_FEASIBILITY.md)），本轮并未实现；AI 对全知识库自动扫描不在本轮；
- 多文档综合问答、可信多段 RAG 引用和跨语义同义词扩展；
- 完整 LaTeX 引擎、OCR 与相关安全审计；
- 团队自律积分排行榜及反作弊框架；
- \`libpng\` ICC 色彩警告资源定位。

本 PR 不改变数据库 schema、导入文件或 Canvas 同步规则；后续需要全库语义检索时，必须单独设计明确授权、模型下载/性能和隐私的完整策略。
