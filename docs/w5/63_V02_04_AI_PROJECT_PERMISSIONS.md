# V0.2-04：本机 AI 项目空间与细粒度授权

> 本轮交付的是**个人本机 AI 项目权限 MVP**，不是完整 Agent/工具执行系统。项目、授权和审计元数据保存在独立 SQLite；当前只有个人任务来源和「生成学习计划草稿」动作接入。没有新增云端项目、团队共享或自动资料读取。

## 本轮交付

1. **本机项目空间**：创建、重命名、归档；最多 50 个。名称和用途只作本地元数据，不会自动发给模型。归档在一个 SQLite 事务中撤销全部资料授权和动作授权，原任务不删除，审计保留。
2. **来源级双重许可**：当前支持逐个个人任务授权：
   - **canReadLocal**：允许 AI 项目在本机读取该任务的受限摘要。
   - **canSendRemote**：额外允许把本轮确实选中的任务摘要发送到当前云端模型；不能在没有本地读取权时单独打开。
   - 授权有效期可选 1 天、7 天、30 天或持续至手动撤销；后端只接受最多 366 天的未来 UTC 时间。过期、撤销或归档后，Main 拒绝新请求。
3. **动作级许可**：默认所有动作拒绝。当前仅开放 **planning.propose**（生成待人工审核的本地学习计划建议）；**task.write**、**calendar.write**、**mail.send**、**file.write**、**external.tool** 尚无执行器，即使 Renderer 构造 IPC 请求也不能授予。
4. **审批令牌按业务域隔离**：AIService 的一次性审批预览绑定 chat、mail 或 project-plan scope；普通聊天的 aiConfirm 不能确认邮件或项目审批令牌，反向也不行。项目规划和邮件协调器分别只能消费自己的审批 scope。
5. **Main 执行层授权**：AI 规划 IPC 必须带项目 ID。Main 在读取任务前检查项目、每个来源的本地读取权、云端发送权及 planning.propose 动作许可；在 AI Key 异步解析后、请求配额预留和付费网络调用前再次检查；模型响应后再次检查来源/动作权限和任务版本。
6. **可审计、少记录**：每次授权、撤销、项目归档和访问允许/拒绝写入独立本机 SQLite。审计仅保存 project/source/action/destination/result/time 元数据，不保存任务标题、正文、提示词、模型回复、API Key 或凭据。每项目最多保留最近 500 条记录。来源/动作的 allowed/denied 是权限检查结果，不代表第三方请求已经发出；实际是否发送以 AIService 请求结果和服务商用量为准。
7. **真实模型结果不越权**：模型只能返回任务 ID、日期、开始分钟。Main 再用现有规划规则核对任务 ID、时间窗、截止日期、重叠和固定课程，产生本机 PlanProposal。不自动应用日历、不改任务、不发送邮件、不写文件。

## 实际发送给云端模型的内容

AI 规划只发送用户在本轮勾选且通过项目双重授权的 1–8 个个人任务的：
- 任务 ID（供主进程验证返回映射）
- 标题（最多 120 字符）
- 截止日期
- 优先级
- 用户选择的规划时间窗设置

不发送任务描述、Canvas 来源 URL、邮件、知识库、其他未选任务、团队资料或项目用途。预览页面显示实际完整 prompt；只有用户明确点击确认才调用已配置的服务商。服务商仍可能处理请求并计费；项目授权不等于服务商零留存或零费用。

## 本机使用步骤

1. 打开「AI 学习助手」，先按既有方式配置自己的 AI 服务商与 API Key。
2. 在「AI 项目空间与权限」中创建项目并写明用途。
3. 对每个希望纳入的个人任务，分别打开「允许项目在本机读取此任务摘要」与「允许将此任务摘要发送给当前云端模型」。默认都关闭；开启云端发送前必须先开启本地读取。
4. 单独开启「允许 AI 在此项目生成学习计划草稿」。这只允许生成待审查建议，不授权写日历。
5. 选择已双重授权的任务，设置规划开始日期，点击预览；核对服务商、模型、全部 prompt 和期限，再决定是否确认。
6. 收到的结果经过 Main 规则校验后只形成学习规划草稿。到现有「学习规划」页面自行查看、编辑和选择性应用。
7. 在权限面板关闭任一授权或归档项目，会立即阻止后续项目请求；已有请求若已发送，无法从第三方撤回。若授权在请求执行期间被撤销，系统不会保存本地规划建议，并会提示请求内容可能已发送、需检查服务商用量。

## 实现范围和明确限制

- 项目是本机个人空间，独立 study-anchor-ai-projects.sqlite，**不进入 Supabase、不自动同步、不分享给团队成员**。
- 当前只有个人任务资源可授权。知识库文档/片段、Canvas 课程/作业、邮件正文/附件、本地文件夹/文件仍使用各自已有授权路径或暂未开放；不能将本轮说成所有连接器已统一纳入项目 ACL。
- 普通自由文本单轮问答仍由用户手工输入并逐次预览；邮件 AI 仍走独立邮件授权协调器。本轮没有自动将项目上下文拼入这些流程。
- 动作执行器尚未开放；没有 Agent 循环、MCP、浏览器、shell、系统文件写入、发信或自动修改日历。
- 授权数据存于本机用户配置目录，不做 OS 加密；它不是密钥或源文件，但本机账户/设备安全仍重要。API Key 继续由原 AI KeyVault 的 OS 加密管理。
- 当前 source grants 上限 100/项目、项目总数上限 50；审计最多 500 条/项目。
- Main 的本机权限检查不替代未来云端团队 RLS，也不保证已经传输到第三方的内容可被远程擦除。

## 自动化测试覆盖

- 严格 schema、UUID、来源类型、远端授权必须从本地读取授权派生；
- 项目创建/重命名/归档、事务撤销、有效期、重新授权、来源撤销；
- 默认无动作许可，只有已实现的 planning.propose 可显式打开；
- 审计不含正文/Key，且记录允许和拒绝；
- AI 规划缺少本地读取、云端传输或动作许可时，Provider prepare/confirm 均不调用；
- 预览后撤销、过期、任务隐藏/完成/变化或项目归档会阻止付费请求；
- AI Key 异步读取之后、网络请求之前再次授权；若在请求期间撤权，则不保存本地草稿；
- 严格 IPC allowlist 与 Windows/macOS CI。

## 真实设备验收（仍需单独执行）

1. 在真实 Windows/macOS 用户配置目录中创建项目、重启后确认项目/授权/审计持久化。
2. 先只开本地读取，确认计划按钮/主进程阻止云端请求；再单独打开云端发送并核对预览。
3. 选择非敏感测试任务，确认一次真实服务商请求和本地规划草稿；确认任务和正式日历未自动改变。
4. 在预览后撤销来源授权、动作授权或归档项目，确认预览失效；再用服务商用量核实没有发出该请求。
5. 在请求进行中撤权/关闭应用，记录服务商是否已处理；应用不得在撤权后持久化本地草稿。
6. 检查本机审计 SQLite 仅含元数据，不含任务标题、提示词、回复或 Key；验证团队空间/云端数据库中没有 AI 项目记录。

命令：

~~~bash
npm run typecheck
npm test
npm run build
~~~

CI 与模拟回归不等于真实第三方 API 计费、OS 账户隔离、跨平台 GUI 或撤权期间网络竞态验收。审批令牌的 chat/mail/project-plan 隔离也有专门的负向测试，防止普通 AI confirm IPC 越过项目授权协调器。
