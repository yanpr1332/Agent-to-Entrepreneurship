# W6-13 AI 辅助学习规划：逐项授权、结构化候选和双重审核

**状态**：依赖 PR #12 的 GitHub 叠放 PR。未经用户审核，不自动合并任何 PR 或部署任何云服务。真实模型/API Key 与桌面 GUI 均未进行联机验收。

## 交付行为

1. 原有「学习规划（离线规则）」仍可离线使用，不要求 Key 或第三方服务。新增**可选 AI 建议**区域，不覆盖原有规则规划。
2. 只从用户的本地任务列表列出可见且未完成的任务；用户必须**逐条勾选最多五项**，默认不勾选。Electron Main 以真实本地数据库验证任务身份、当前状态、标题、截止日期和优先级。Renderer 只能传已选任务 UUID 和既有合法规划时间窗；不能伪造标题、备注、Canvas 资料或额外上下文。
3. Main 用勾选的任务构造一份**可完整预览**的单轮请求。**仅**外发所选任务的 ID、前 120 字标题、截止日期、优先级和已选择的日期/空闲时间窗；不会外发任务备注、Canvas Token、邮箱正文、知识库文本、Supabase 工作空间或用户未选择的任务。
4. 用户点击「预览」不会发起 API/计费；必须再次明确点击「确认发送」才调用 PR #12 的 HTTPS OpenAI Responses API。一次性确认 2 分钟过期，使用 PR #12 既有每日请求预算、超时、加密 Key 与脱敏错误处理。
5. 模型应**只**返回紧凑 JSON：`{"slots":[{"taskId":"UUID","day":"YYYY-MM-DD","startMinute":1080}]}`。客户端不执行或相信模型生成的任意代码、HTML、路径或任务内容。
6. Main 对 JSON 严格解析并限制 1–5 条；逐项检查真实任务 ID、去重、范围、15 分钟时间刻度、用户给定每日空窗、截止日期以及与已确认规划和其他 AI 块的冲突。**任一候选不合法则整个 AI 结果被拒绝**，不自动改动任何正式任务或日历。模型的非 JSON 回复、时间冲突和格式错误会消耗该次已确认 API 尝试，程序不自动重试。
7. 合法 AI 结果仅保存为原有 `ate-plans.sqlite` 的 `proposed` 状态（待审核）。现有 StudyPlanner UI 会显示候选、允许编辑日期/时间、仅选择部分应用、再次确认以及批次撤销。**没有直接把模型输出写到正式日历的接口**。
8. 请求前与网络返回后均对选中任务进行数据库快照比对；其间任务被编辑、隐藏或完成时，拒绝沿用过期上下文。最终应用时，既有 Planner 还会第三次验证任务及时间冲突。
9. 在本地数据库中仅持久化**被验证的候选安排**与既有任务源快照；不保存原始提示词、模型原始 JSON、个人 Key 或 API token。AI 返回的建议使用固定的“AI 建议”风险提示作为理由，不把未验证的模型解释作为事实或证据。

## 安全说明

- 本轮不做自动智能日历写入、不做背景模型调用，也没有工具调用权限。
- 仍然没有真实学校固定课表、外部日历的课程锁定事项、跨时区冲突判定。只能检查**本应用内已确认**时间块，请用户在应用前自行核对课程、考试及会议。
- 模型可能错误地选择空窗、遗漏任务或返回无法解析的 JSON；本地约束校验和人工二次确认不能保证学习建议学术正确。
- 每日次数限制不是实际金额上限。模型可能返回格式错误仍已计费。
- 只有调用时用户明确选择的任务摘要会外发；连接 Key 或打开规划页面不会触发模型调用。
- 未经用户明确请求，不向 API 提交真实私人课程文档、邮箱正文或聊天历史。

## CI 与本地验收

Vitest 应覆盖：最多五个 UUID 的授权边界；不会读取备注/未选任务；预览不会产生真实网络调用；一次性确认；任务在调用前/返回后变化即拒绝；输出 JSON 解析和未知任务/重复 ID、时间超窗/过截止/冲突验证；合法候选只是 proposed，仍能通过原有 apply/undo 流程；原有离线规则规划未退化。

真实联机验收（用户自己的设备与合法测试 API Key，**不在 ChatGPT/GitHub 传递 Key**）：
1. PR #12 和 #13 按依赖顺序合并并确认程序启动；
2. 先手动创建两个无敏感内容的测试任务；仅勾选其中一个，点击预览，检查未选任务和备注不在外发文本中；
3. 明确确认一次模型调用，观察待审核的时间块（或模型输出格式错误后的安全提示）；
4. 修改时间、只应用一段到日历，再撤销整批，确保任务截止日期与完成状态未变化；
5. 修改某任务再试用之前的候选，确认 Main 拒绝过期规划；
6. 回到原离线规则模式，确认其不依赖 Key 继续可用。
