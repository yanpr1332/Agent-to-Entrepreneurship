# ALPHA-TIME-002：专注标题、实际时段与日历（PR #27）

> 当前实现属于 ALPHA-TIME-002 的**专注记录子范围**，不等同于整项任务/课程时间模型完成。代码检查及 CI 不能替代 Windows/macOS 人工 GUI 验收。

## 本轮实现

- **专注标题**：开始专注前自由输入（1–120 字符）；专注中的标题锁定。保存后在「专注与自律 → 最近记录」可修改标题，修改不会重新发积分。
- **记录真实会话时段**：开始记录用户设备的 ISO 开始时刻，倒计时完成取真实预计结束时刻；提前结束则取当时结束时刻。另存有效专注秒数，暂停期间的墙上钟表时间不会被冒充有效专注。
- **日历显示**：月历用圆点提示有实际专注的日期，日/周时间线新增「实际专注」类型，选中日期的详情单列实际记录。跨午夜按用户设备的当地日期拆分；两天展示的是同一场会话，不应重复增加积分。
- **历史兼容**：原有记录的开始时间是从结束时刻和有效秒数倒推的，无法恢复中途暂停。迁移为 \`timeSource = estimated\`，历史记录仍显示，但**不出现在真实专注日历中**。新记录为 \`recorded\`。
- **导航**：FocusTimer 始终保持 React 挂载，打开其他模块不应意外中断当前应用内计时。仍需用户点击「记录完成」或「结束并记录」才会写入本地 SQLite。
- **隐私**：标题、时间和积分仅保存在本机，不自动同步到 Supabase、Canvas、邮箱或 AI。渲染标题为纯文本，不接受 HTML 执行。

## SQLite v4 → v5 升级说明

\`ate-local.sqlite\` 的 \`PRAGMA user_version\` 从 **4** 升到 **5**。新增字段：

- \`focus_sessions.title\`：非空文本；历史默认「专注学习」。
- \`focus_sessions.time_source\`：\`recorded\` 或 \`estimated\`，历史默认 \`estimated\`。

主进程先调用 \`backupBeforeMigration(userData, "ate-local.sqlite", 5)\`，用 SQLite 在线备份 API 生成校验过的快照，然后才允许主库执行事务内 \`ALTER TABLE\` 并更新 \`user_version\`。迁移中失败要回滚事务。快照在 \`ATE_USER_DATA_DIR/backups/pre-migration-ate-local.sqlite-v4-...\` 下，**未加密**，须保护本地目录，不得上传包含私人任务的快照。

**升级后的 v5 库不能直接被旧的 v4 程序打开。** 回退到旧程序前，必须先关闭应用并通过受审查的离线恢复流程还原匹配版本的备份；仓库尚无用户友好的安全恢复 UI，不能以简单删除当前库替代恢复。建议首次集中测试始终使用隔离的 \`ATE_USER_DATA_DIR\`。

历史数据库升级后，标题可以修改，但积分、起止时刻和 time_source 不可通过修改标题的 IPC 变更。旧客户端若通过旧专注协议写入未携带起止时刻的记录，仍会保存，但只能标识为估算时段。

## 本地集中 GUI 验收脚本

1. 更新到 PR #27 分支，在 PowerShell 设置 \`$env:ATE_USER_DATA_DIR = "$env:LOCALAPPDATA\ATE-alpha-time-002"\`，启动 \`npm run dev\`，在工作台确认 SQLite 已连接。
2. 打开「专注与自律」，输入标题「复习线性代数」、专注 1 分钟，开始。计时期间切换到「日历与任务」再返回，验证计时器没有重置。
3. 完成后点击「记录完成」，在历史列表看到标题和有效分钟与积分；点击「修改标题」改为「复习矩阵」，确认积分不变。
4. 返回日历，选中刚才实际发生的日期：月视图日期有圆点，日/周视图有「实际专注」记录，日期详情也有同样标题、时段。
5. 再做一个 2 分钟会话，约 30 秒时暂停并在稍后继续，检查显示的日历起止范围包含暂停，但有效分钟和积分仍按真实有效计时计算。提前结束不会获得完整完成积分。
6. 在开发测试数据中创建/打开旧版 v4 库，运行新版本，核对生成的 v4 迁移备份、旧历史仍能显示、但不会错误进入日历。禁止直接使用私人旧库做破坏性试验。
7. 跨午夜拆分由 Vitest 固定时间样例覆盖；如人工做跨午夜测试，须确认两日均能看到同一标题而积分不翻倍。
8. 关闭应用并用**相同数据目录**重启，检查专注标题修改结果、实际时间及积分没有丢失。

在任一环节异常时记录操作步骤、预期/实际结果及脱敏截图；标注为“失败/待验收”，不要跳过。Node 24 / npm 11 / Electron 安装、沙箱兼容和诊断步骤见 [根 README](../../README.md)。

## 未在本轮实现

- 任务可选截止时刻及多个执行时段，已规划时间块的更完整编辑；
- 固定课程的整组/未来系列修改；
- 分段暂停明细可视化和应用崩溃后的专注恢复；
- 小组排行榜和可信反刷分时间来源；
- Markdown/HTML/LaTeX 安全渲染、模糊/AI 语义搜索；
- 完整安全备份恢复 GUI 与 macOS/Windows 安装包人工验收。

时间由用户设备提供，不是服务器认证的防作弊证明；**禁止把本轮本地计时直接当成公开团队排行榜的可信依据**。时钟调整、夏令时、长时间暂停、历史 500 条展示上限仍需后续专项测试。
