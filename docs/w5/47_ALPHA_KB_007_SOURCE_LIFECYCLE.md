# ALPHA-KB-007 — 批量资料导入、只读来源检查与选择性刷新

> 开发批次 2026-11-25；目标是本机知识库的文件来源生命周期，不更改团队同步权限、Embedding 模型供应链或 #48 UI 改版。

## 产品目标

原有用户要更新十几份讲义时，需要逐份打开系统文件选择器再次导入；无法先知道哪些原文件已修改、丢失或格式损坏。本轮提供**只在用户明确操作时执行**的批量导入与“先检查、后勾选、再确认更新”工作流。不监控任意文件夹、不后台扫描、不上传原文件，也不声称实现 Obsidian Vault 自动同步。

## 接口和权限边界

- 旧 `knowledge:import` 单文件逻辑保留。新增 `knowledge:batch-import`：仅 Electron Main 原生多文件选取（最多 20 份），沿用 PDF/Markdown/HTML/TeX/TXT 受限读取、UTF-8、2 MiB 文本 / 12 MiB PDF、120 页与拒绝符号链接规则。每份依次导入，失败/重复单独报告；保留旧快照，其他文件不受影响。
- `knowledge:source-audit`：仅接受 1–20 个已存在的知识库 UUID；Main 从已有 SQLite 中取得**之前由用户选择导入的**文件路径。只读检查原文 SHA-256，区分“未变化/已变化/丢失/无法安全读取/检查途中版本改变”；不改知识库、复习卡、向量或硬盘原文。Renderer 不能传本机任意路径。
- `knowledge:source-refresh`：独立显式确认，只允许有限的 `documentId, expectedRevision, observedHash`，拒绝未知字段、重复 ID、无效散列和 >20 项。Main 重新从 SQLite 查原路径并读取，必须与上次检查到的 SHA-256 一致、文档版本未变化、格式和规范化真实路径一致，才允许调用原有单文件导入事务。文件丢失、旧哈希被替换、版本竞争、解析失败都逐条失败关闭、保留原快照。
- 已存在的 HTML/TeX 源文档用规范化 UTF-8 文本哈希比对；PDF 用文件原始字节 SHA-256，页码保持现有提取语义。所有来源路径只由本机 Main 读取；Renderer 仅收到文档标题、UUID、状态和检查时的散列，不显示读取失败的私有文件异常堆栈。
- 重导入真实变化会沿用知识库的版本升级逻辑，重新构建全文索引、使旧 Embedding 派生数据失效，并把旧复习卡、知识图谱引用标成待核对；旧证据历史和复习进度保留，不自动宣布过期内容可信。不会删除原始文件，也不会擦除此前备份里的旧文本。
- 本轮没有数据库 Schema 升级，也没有新增 npm 包。依赖已有知识库 SQLite v6 和已审核的 PDF/文本读取器。

## 用户工作流

1. 个人知识库 → 批量导入与原文更新检查 → 点击“批量选择文件并导入”，在原生对话框选取最多 20 份；查看逐份新增、更新、未变化、重复或失败报告。
2. 点击“检查已导入原文件是否变化”，在清单勾选最多 20 份之前导入的文档；**此时才**读取原文件进行只读审计。丢失/不可读时，不自动删除之前的本机资料。
3. 检查结果中仅“已变化”项可被选择刷新；取消不写数据。确认后 Main 复查真实文件与数据库版本并逐份更新，失败项不覆盖快照。
4. 更新成功后全文搜索命中新内容；旧复习卡按 KB-006 要求由用户人工核对。源文件移动后，需要通过原生选择器再次导入新路径；不会自动猜测并修改来源引用。

## 安全与测试

- 对原生选择数量、强制 UUID、重名/重复路径、未知字段、数字范围、文件大小/格式、改动后又发生磁盘变更、SQLite 版本竞争、目录软链接重定向、删除、PDF 页码与复习卡过期均应测试。
- 不允许 Renderer 直接传路径进行刷新，不通过外部云端轮询更新本地知识库。无静默定时器、无异步后台任务。
- 双平台自动验收：npm ci / typecheck / npm test / electron-vite build / 已打包离线 Worker smoke。真实 Windows/macOS 原生多选对话框、包含中文路径的文件夹权限、PDF 逐页解析耗时、批量部分失败恢复仍需用户本机 GUI 验收。CI 通过不等于真实设备验收。
- 避免把私人源文件、敏感摘要、原文路径、凭据放到 PR、Issue 或公共测试产物。

## 下一批次

真正神经 ONNX/E5/BGE 的供应链、量化权重、离线 tokenizer 与 CPU 推理必须独立实测；本轮不是神经 Embedding 的实现。目录递归授权、后台文件监控和原文件变更通知不属于本轮，必须再讨论隐私和平台权限设计。
