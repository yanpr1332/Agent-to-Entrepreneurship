# 产品定位与使用场景

## 核心问题

大学生的任务分散在教学平台、邮箱、课表、聊天、日历、文件夹、笔记软件中：信息需要重复登记；截止时间与实际学习时间割裂；知识资料难以复用；团队工作与个人日程不衔接。

## 产品目标

打造面向大学生的 AI 辅助个人管理平台，将信息收集、计划制定、学习资源、专注执行、团队协作及复盘连成闭环。软件应当帮助用户**减少管理成本**，而不是增加新的记录负担。

产品由八个一级模块组成：日历与任务、个人知识库、专注与自律、小组协作、AI 智能规划、数据接入与扩展、**邮件管理与 AI 通信**、个人工作台。邮件模块有独立界面和业务流程；工作台仅做跨模块汇总。

项目名 `Agent-to-Entrepreneurship` 为暂定仓库名，不表示必须商业化；公益、个人作品、学生社区项目、研究性项目均是可能的发展方向。

## 用户范围

### 首批目标人群

- 上海交通大学本科生与研究生。
- 有多门课程、作业、考试和个人事务的学生。
- 同时参加课程小组、科研、竞赛、社团项目的学生。

### 扩展目标

- 其他高校学生（通过可替换的教育平台连接器）。
- 有相似工作流的个人用户与小型学习团队。

## 三个关键使用场景

### 场景 A：课程作业

Canvas/教务平台同步作业或课表 → 任务收件箱 → 检查截止时间及来源 → 拆分工作量 → 规划到可用时段 → 提醒及专注执行 → 更新状态。

### 场景 B：课程学习与复习

上传课件、PDF 和录音 → 转写与索引 → 关联课程和知识点 → 有出处的 AI 问答 → 生成复习卡片/练习 → 结合考试与遗忘情况安排复习。

### 场景 C：小组项目

创建团队项目 → 分配或认领任务 → 个人日程显示自己负责的事项 → 共享文件/讨论/会议纪要 → 更新项目看板 → 负责人验收 → 自动形成周报。

### 场景 D：邮件驱动的事项管理与沟通

经授权连接邮箱 → 同步指定邮件 → 提取会议、截止日期、待办和附件 → 用户确认后进入统一收件箱／日历／任务 → AI 根据上下文拟写新邮件或回复 → 用户审阅收件人、正文和附件后明确确认发送 → 保存发送状态与原始邮件关联。

## 差异化

1. 以高校教学与学习为起点的深度数据集成。
2. 任务、时间、课程、知识条目、项目之间具有结构化关联。
3. AI 建议可审查、可回退，并受权限限制。
4. 规划、执行、反馈形成可持续优化的闭环。

## 衡量是否有用

- 首次配置完成率、课程成功导入率。
- 任务创建/导入所需时间和自动导入占比。
- AI 规划被采纳的比例与调整频率。
- 每周活跃率、4 周留存率及用户主观满意度。
- 截止任务完成率、实际耗时与预估耗时偏差。

不以“用户在软件中停留更久”为主要目标。
